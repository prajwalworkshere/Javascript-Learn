## 2. What Is JavaScript Syntax?

### Definition

**JavaScript syntax is the set of rules that determines how JavaScript code must be written so that the JavaScript engine can parse it correctly.**

In simple words, syntax is the grammar of JavaScript.

Just as a language follows grammatical rules, a programming language follows rules for writing instructions.

### Example 1: Correct syntax

```javascript
let age = 21;

console.log(age);
```

Output:

```text
21
```

This code follows valid JavaScript syntax.

### Example 2: Incorrect syntax

```javascript
let = age 21;
```

This code does not follow the rules for a variable declaration, so the engine reports a syntax error.

### Why is syntax important?

Syntax helps the JavaScript engine understand:

- Where statements begin and end.
- How variables are declared.
- How expressions are structured.
- Where blocks of code begin and end.
- How functions are declared and called.

**Remember:** Correct syntax does not automatically mean your program's logic is correct. A program can have valid syntax and still produce the wrong answer.

## 3. JavaScript Statements

### Definition

A **statement** is an instruction or declaration that forms part of a JavaScript program.

Statements tell JavaScript to perform an action, declare a variable, make a decision, repeat code, or perform other operations.

### Example

```javascript
let a = 10;
let b = 20;

console.log(a + b);
```

This program contains three statements:

1. `let a = 10;` — declares a variable and initializes it.
2. `let b = 20;` — declares another variable and initializes it.
3. `console.log(a + b);` — calls a function to print the result.

Output:

```text
30
```

### Common types of statements

| Statement type       | Example                  | Purpose                                |
| -------------------- | ------------------------ | -------------------------------------- |
| Variable declaration | `let age = 21;`          | Declares a variable                    |
| Expression statement | `total = 10 + 20;`       | Evaluates an expression as a statement |
| Conditional          | `if (age >= 18) { ... }` | Executes code conditionally            |
| Loop                 | `for (...) { ... }`      | Repeats instructions                   |
| Return               | `return total;`          | Returns a value from a function        |
| Block                | `{ let x = 10; }`        | Groups statements into a block         |

Some of these constructs will be covered in greater depth in later topics.

## 4. JavaScript Expressions

### Definition

An **expression** is a piece of JavaScript code that evaluates to a value.

Expressions can contain literals, variables, operators, function calls, and other expressions.

### Example 1: Arithmetic expression

```javascript
10 + 20
```

Result:

```text
30
```

The expression evaluates to the number `30`.

### Example 2: Variable expression

```javascript
let price = 100;
```

Here, `100` is a numeric literal used to initialize the variable.

The expression:

```javascript
price * 2
```

evaluates to:

```text
200
```

### Example 3: Comparison expression

```javascript
10 > 5
```

Result:

```text
true
```

### Example 4: String expression

```javascript
"Hello" + " World"
```

Result:

```text
Hello World
```

### Statement vs expression

| Statement                                             | Expression                                                        |
| ----------------------------------------------------- | ----------------------------------------------------------------- |
| Represents an instruction or declaration              | Evaluates to a value                                              |
| Examples include `let x = 10;` and `if (...) { ... }` | Examples include `10 + 20` and `x > 5`                            |
| Can contain expressions                               | Can be used within statements                                     |
| Does not always evaluate to a value                   | Always evaluates to a value, though that value can be `undefined` |

A function call is an expression, for example, and it may return a value or evaluate to `undefined`.

### Important example

```javascript
let result = 10 + 20;
```

Breakdown:

- `let result = ...;` is a variable declaration statement.
- `10 + 20` is an arithmetic expression.
- The expression evaluates to `30`.
- The variable `result` receives the value `30`.

## 5. How JavaScript Executes Code

JavaScript normally executes synchronous statements in program order within a given execution context.

Let's see a simple example.

```javascript
console.log("First");

let a = 10;

console.log(a);

let b = 20;

console.log(a + b);

console.log("Last");
```

Output:

```text
First
10
30
Last
```

### Dry run

| Step | Instruction             | Result           |
| ---- | ----------------------- | ---------------- |
| 1    | `console.log("First");` | Prints `First`   |
| 2    | `let a = 10;`           | `a` becomes `10` |
| 3    | `console.log(a);`       | Prints `10`      |
| 4    | `let b = 20;`           | `b` becomes `20` |
| 5    | `console.log(a + b);`   | Prints `30`      |
| 6    | `console.log("Last");`  | Prints `Last`    |

### Execution flow

```text
Start
  |
  v
Print "First"
  |
  v
Create a = 10
  |
  v
Print a
  |
  v
Create b = 20
  |
  v
Calculate a + b
  |
  v
Print 30
  |
  v
Print "Last"
  |
  v
End
```

This is the normal flow for these simple synchronous statements.

**Important:** JavaScript does not always finish every operation before moving to the next statement. Asynchronous operations, such as timers and network requests, introduce additional scheduling behavior that you will study later.

## 6. JavaScript Comments

### Definition

**Comments are notes written in source code for humans to read. JavaScript does not execute comments as program instructions.**

Comments help explain code, record assumptions, and temporarily disable code during debugging.

JavaScript has two common comment styles.

### 6.1 Single-line comments

A single-line comment begins with `//`.

```javascript
// Store the student's marks
let marks = 85;

// Display the marks
console.log(marks);
```

Output:

```text
85
```

Everything after `//` on that line is treated as a comment.

### 6.2 Multi-line comments

Multi-line comments begin with `/*` and end with `*/`.

```javascript
/*
This program calculates
the total cost of products.
*/

let price = 100;
let quantity = 3;

console.log(price * quantity);
```

Output:

```text
300
```

### 6.3 Using comments to explain logic

```javascript
// Price of one notebook
const price = 50;

// Number of notebooks purchased
const quantity = 4;

// Calculate the total cost
const total = price * quantity;

console.log(total);
```

Output:

```text
200
```

### 6.4 Temporarily disabling code

```javascript
console.log("First");

// console.log("This line is commented out");

console.log("Third");
```

Output:

```text
First
Third
```

### Good commenting practices

- Explain why a decision was made when it is not obvious.
- Keep comments accurate as the code changes.
- Avoid comments that simply repeat what the code already clearly says.
- Use meaningful variable names so the code is easier to understand.

## 7. Semicolons in JavaScript

### What is a semicolon?

A semicolon (`;`) is used to terminate many JavaScript statements.

Example:

```javascript
let age = 21;
console.log(age);
```

Output:

```text
21
```

### Are semicolons mandatory?

JavaScript has a feature called **Automatic Semicolon Insertion (ASI)**.

Under certain rules, the parser inserts semicolons when the source code omits them.

Therefore, this can work:

```javascript
let a = 10
let b = 20

console.log(a + b)
```

Output:

```text
30
```

However, ASI is not simply the rule "put a semicolon wherever a line ends." Some line breaks can change how code is interpreted.

### Example of a surprising line break

```javascript
function getValue() {
    return
    10;
}

console.log(getValue());
```

Output:

```text
undefined
```

Why?

Because the line break immediately after `return` triggers automatic semicolon insertion in this context. The function returns without a value.

The intended code is:

```javascript
function getValue() {
    return 10;
}

console.log(getValue());
```

Output:

```text
10
```

### Best practice for beginners

Use semicolons consistently in your learning notes and programs:

```javascript
const name = "Prajwal";
const age = 21;

console.log(name);
console.log(age);
```

Consistency makes code easier to read and helps you avoid some confusing cases involving automatic semicolon insertion.

## 8. Curly Braces `{ }`

Curly braces are used to define blocks of code and object literals, among other things.

In this topic, focus on their role in blocks.

### Example

```javascript
if (true) {
    console.log("Inside the block");
}

console.log("Outside the block");
```

Output:

```text
Inside the block
Outside the block
```

The braces group the statement belonging to the `if` statement.

### Visual representation

```text
if (true) {
    ┌────────────────────────────┐
    │ console.log("Inside...");  │
    └────────────────────────────┘
}

console.log("Outside...");
```

### Why do blocks matter?

Blocks are commonly used with:

- `if` and `else`.
- Loops.
- Functions.
- `try` and `catch`.
- Other language constructs that require a statement block.

You will explore these uses in later topics.

### Common mistake: missing a closing brace

Incorrect:

```javascript
if (true) {
    console.log("Hello");
```

The block is incomplete. The parser reports a syntax error because the closing brace is missing.

Correct:

```javascript
if (true) {
    console.log("Hello");
}
```

## 9. Parentheses `( )`

Parentheses have several uses in JavaScript.

### 9.1 Grouping expressions

```javascript
console.log((10 + 20) * 2);
```

Output:

```text
60
```

The expression inside the parentheses is evaluated first.

Without those parentheses:

```javascript
console.log(10 + 20 * 2);
```

Output:

```text
50
```

Multiplication has higher precedence than addition, so JavaScript calculates `20 * 2` first.

### 9.2 Function calls

```javascript
console.log("Hello");
```

The parentheses contain the argument passed to `console.log()`.

### 9.3 Conditions

```javascript
let age = 21;

if (age >= 18) {
    console.log("Adult");
}
```

Output:

```text
Adult
```

The parentheses contain the condition being tested.

## 10. Square Brackets `[ ]`

Square brackets are used for array literals and for accessing array elements or certain object properties.

### Example: array literal

```javascript
const numbers = [10, 20, 30];

console.log(numbers);
```

Output:

```text
[10, 20, 30]
```

### Example: accessing an element

```javascript
const numbers = [10, 20, 30];

console.log(numbers[0]);
console.log(numbers[1]);
```

Output:

```text
10
20
```

JavaScript arrays use zero-based indexing, so the first element is at index `0`.

## 11. JavaScript Is Case-Sensitive

### Definition

**JavaScript is case-sensitive, which means uppercase and lowercase letters are treated as different characters in identifiers.**

### Example

```javascript
let name = "Prajwal";

console.log(name);
```

Output:

```text
Prajwal
```

Now consider:

```javascript
let name = "Prajwal";

console.log(Name);
```

This normally produces a `ReferenceError` because `Name` and `name` are different identifiers, and `Name` has not been declared.

### More examples

These identifiers are different:

```javascript
let age = 21;
let Age = 25;
let AGE = 30;

console.log(age);
console.log(Age);
console.log(AGE);
```

Output:

```text
21
25
30
```

### Built-in names are also case-sensitive

Correct:

```javascript
console.log("Hello");
```

Incorrect:

```javascript
Console.log("Hello");
```

`Console` and `console` are different identifiers. In a standard environment, `Console` is not the lowercase console object used in this example.

### Best practice

Use consistent naming conventions:

- `studentName`
- `totalPrice`
- `calculateTotal`

These examples use camelCase, a common convention in JavaScript.

## 12. Whitespace and Indentation

Whitespace includes spaces, tabs, and line breaks.

In many JavaScript contexts, extra whitespace between tokens does not change the program's meaning.

### Example

```javascript
let a = 10;
let b = 20;
console.log(a + b);
```

This can also be written as:

```javascript
let    a    =    10;

let b=20;

console.log( a+b );
```

Both programs print:

```text
30
```

However, formatting the code consistently makes it easier to read.

### What is indentation?

Indentation means adding spaces at the beginning of lines to show the structure of the code.

Readable version:

```javascript
if (true) {
    console.log("First statement");
    console.log("Second statement");
}
```

Poorly formatted version:

```javascript
if(true){console.log("First statement");console.log("Second statement");}
```

Both are valid, but the first is easier to maintain.

### Recommended style

- Use consistent indentation, commonly two or four spaces.
- Put related statements on separate lines.
- Keep braces aligned.
- Separate logical sections with blank lines.

Indentation generally affects readability rather than program behavior, although whitespace can be significant in particular lexical situations, such as separating identifiers or creating a line break after `return`.

## 13. String Quotes

JavaScript supports single quotes, double quotes, and backticks for strings.

### Single quotes

```javascript
let name = 'Prajwal';
console.log(name);
```

### Double quotes

```javascript
let name = "Prajwal";
console.log(name);
```

Both print:

```text
Prajwal
```

### Backticks

```javascript
let name = `Prajwal`;
console.log(name);
```

This also prints:

```text
Prajwal
```

Backticks additionally support template literals, which allow interpolation and multiline strings.

Example:

```javascript
const name = "Prajwal";
const age = 21;

console.log(`My name is ${name} and I am ${age} years old.`);
```

Output:

```text
My name is Prajwal and I am 21 years old.
```

The `${...}` expressions inside the template literal are evaluated and their values are inserted into the string.

You will study template literals in greater depth when learning strings.

## 14. Syntax Errors vs Runtime Errors

These are two important categories of errors.

### 14.1 Syntax error

A syntax error occurs when code violates the language's syntax rules.

Example:

```javascript
let = 10;
```

This declaration is invalid and produces a syntax error.

Another example:

```javascript
if (true) {
    console.log("Hello");
```

The closing brace is missing.

### 14.2 Runtime error

A runtime error occurs while the program is running.

Example:

```javascript
console.log(userName);
```

If `userName` has not been declared in the current scope, JavaScript normally throws a `ReferenceError` when it tries to evaluate the identifier.

### 14.3 Logical error

A logical error means the program runs but produces an incorrect result.

Example:

```javascript
let length = 10;
let width = 5;

let area = length + width;

console.log(area);
```

Output:

```text
15
```

There is no syntax error here, but if the goal is to calculate the area of a rectangle, the formula is wrong.

Correct code:

```javascript
let length = 10;
let width = 5;

let area = length * width;

console.log(area);
```

Output:

```text
50
```

### Comparison table

| Error type    | Meaning                              | Example                                           |
| ------------- | ------------------------------------ | ------------------------------------------------- |
| Syntax error  | Code violates syntax rules           | Missing closing brace                             |
| Runtime error | An error occurs during execution     | Reading an undeclared identifier                  |
| Logical error | Code runs but gives the wrong result | Using addition instead of multiplication for area |

## 15. Code Execution Dry Run

A dry run means tracing a program manually to understand what happens at each step.

Consider this program:

```javascript
let a = 5;
let b = 10;

let c = a + b;

console.log(c);

a = 20;

console.log(a + b);
```

### Step-by-step dry run

| Step | Code                  | Value changes        | Output |
| ---- | --------------------- | -------------------- | ------ |
| 1    | `let a = 5;`          | `a = 5`              | —      |
| 2    | `let b = 10;`         | `b = 10`             | —      |
| 3    | `let c = a + b;`      | `c = 15`             | —      |
| 4    | `console.log(c);`     | No change            | `15`   |
| 5    | `a = 20;`             | `a = 20`             | —      |
| 6    | `console.log(a + b);` | Calculates `20 + 10` | `30`   |

Final output:

```text
15
30
```

### Memory-style view

After Step 3:

```text
a  ──> 5
b  ──> 10
c  ──> 15
```

After Step 5:

```text
a  ──> 20
b  ──> 10
c  ──> 15
```

Notice that `c` remains `15`. Its initialization expression was calculated when the declaration ran; changing `a` later does not automatically recalculate `c`.

This is an important principle: ordinary variable assignments store values. They do not automatically maintain a relationship between separate variables.

## 16. Practical Example: Shopping Bill

Let's apply statements, expressions, comments, and execution order to a practical problem.

```javascript
// Price of one item
const itemPrice = 250;

// Number of items purchased
const quantity = 3;

// Calculate the bill
const total = itemPrice * quantity;

// Display the result
console.log("Item price:", itemPrice);
console.log("Quantity:", quantity);
console.log("Total bill:", total);
```

Output:

```text
Item price: 250
Quantity: 3
Total bill: 750
```

### Dry run

1. `itemPrice` receives `250`.
2. `quantity` receives `3`.
3. `itemPrice * quantity` evaluates to `750`.
4. `total` receives `750`.
5. The three `console.log()` statements print the values.

### Concepts used

- `const` declarations.
- Numeric literals.
- Arithmetic expressions.
- Statements.
- Comments.
- Function calls.
- Sequential execution.

## 17. Common Beginner Mistakes

### Mistake 1: Incorrect capitalization

Incorrect:

```javascript
Console.log("Hello");
```

Correct:

```javascript
console.log("Hello");
```

### Mistake 2: Missing quotation marks

Incorrect:

```javascript
console.log(Hello);
```

Correct:

```javascript
console.log("Hello");
```

Without quotation marks, `Hello` is treated as an identifier rather than a string literal.

### Mistake 3: Missing braces

Incorrect:

```javascript
if (true) {
    console.log("Hello");
```

Correct:

```javascript
if (true) {
    console.log("Hello");
}
```

### Mistake 4: Confusing `=` and `==`

For now, remember:

- `=` assigns a value.
- `==` compares values using loose equality.
- `===` compares values without coercing their types.

Example:

```javascript
let age = 21;

console.log(age === 21);
```

Output:

```text
true
```

You will study operators and comparisons in a later topic.

### Mistake 5: Assuming every new line ends a statement

Automatic semicolon insertion follows specific rules. Some line breaks can produce unexpected behavior, especially around `return`.

### Mistake 6: Assuming code can be syntactically correct but must be logically correct

This code runs but does not calculate a rectangle's area correctly:

```javascript
let area = 10 + 5;
```

Always check whether your formula matches the problem you are solving.

## 20. Interview and Viva Questions

### Q1. What is JavaScript syntax?

JavaScript syntax is the set of rules that determines how JavaScript programs must be written and structured so that the engine can parse them.

### Q2. What is a statement?

A statement is an instruction or declaration that forms part of a JavaScript program.

### Q3. What is an expression?

An expression is a piece of code that evaluates to a value.

### Q4. What is the difference between a statement and an expression?

An expression evaluates to a value, while a statement represents an instruction or declaration. Statements often contain expressions.

### Q5. What are comments?

Comments are notes in source code that are not executed as program instructions. JavaScript supports `//` single-line comments and `/* ... */` multi-line comments.

### Q6. Are semicolons mandatory in JavaScript?

Not in every case. JavaScript has automatic semicolon insertion, but using semicolons consistently is a useful practice.

### Q7. Is JavaScript case-sensitive?

Yes. Identifiers such as `name`, `Name`, and `NAME` are treated as different identifiers.

### Q8. What is indentation?

Indentation is the use of leading spaces or tabs to show code structure and improve readability.

### Q9. What is a syntax error?

A syntax error occurs when code violates JavaScript's syntax rules and cannot be parsed as valid code.

### Q10. What is a runtime error?

A runtime error occurs during program execution, such as attempting to access an undeclared identifier.

### Q11. What is a logical error?

A logical error occurs when the program runs but does not produce the intended result.

### Q12. What is Automatic Semicolon Insertion?

Automatic Semicolon Insertion (ASI) is a JavaScript parsing mechanism that inserts semicolons in certain situations when they are omitted from the source code.

### Q13. Does JavaScript always execute statements in the order written?

Synchronous statements in the same execution context generally execute in program order. Asynchronous operations introduce additional scheduling behavior.

### Q14. What are curly braces used for?

Curly braces define blocks and object literals, among other uses. Blocks group statements in constructs such as functions, loops, and conditional statements.

## 21. Quick Revision Notes

- **Syntax:** Rules for writing valid JavaScript.
- **Statement:** An instruction or declaration.
- **Expression:** Code that evaluates to a value.
- **Comment:** A note ignored as an executable instruction.
- `//`: Single-line comment.
- `/* ... */`: Multi-line comment.
- `;`: Statement terminator, with ASI available in certain situations.
- `{ }`: Used for blocks and object literals, among other purposes.
- `( )`: Used for grouping expressions, function calls, and conditions.
- `[ ]`: Used for arrays and property access.
- **Case-sensitive:** `name` and `Name` are different identifiers.
- **Syntax error:** Code cannot be parsed as valid syntax.
- **Runtime error:** An error occurs during execution.
- **Logical error:** Code runs but produces the wrong result.
- **Dry run:** Manually tracing each step of a program.
