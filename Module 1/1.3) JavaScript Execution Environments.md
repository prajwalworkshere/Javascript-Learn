## 2. What Is a JavaScript Execution Environment?

### Definition

A **JavaScript execution environment** is the collection of software components and facilities that allow JavaScript code to run and interact with its surroundings.

It includes a JavaScript engine and the additional APIs and services available to the program.

For example, JavaScript can run in:

1. A web browser, such as Google Chrome.
2. Node.js on your computer or a server.
3. Other environments that embed a JavaScript engine.

### Understand with a real-life example

Imagine JavaScript is a person who needs to perform a task.

- **JavaScript code:** Instructions given to the person.
- **JavaScript engine:** The person's ability to understand and execute the instructions.
- **Execution environment:** The workplace, tools, and facilities available to that person.

A person working in an office has different tools from someone working in a kitchen. Similarly, JavaScript running in a browser has different built-in facilities from JavaScript running in Node.js.

### Example

```javascript
console.log("Hello, JavaScript!");
```

Output:

```text
Hello, JavaScript!
```

This code can run in both a browser's developer console and Node.js because both environments support `console.log()`.

However, the environments do not provide exactly the same features.

## 3. What Is a JavaScript Engine?

### Definition

A **JavaScript engine** is a software component that parses JavaScript source code and executes it according to the JavaScript language specification.

In simple words, the engine is responsible for understanding your JavaScript instructions and making them run.

### Popular JavaScript engines

| Engine | Commonly associated with |
|---|---|
| V8 | Google Chrome and Node.js |
| SpiderMonkey | Mozilla Firefox |
| JavaScriptCore | Safari |

These are examples, not a complete list.

### Example

```javascript
let a = 10;
let b = 20;

let sum = a + b;

console.log(sum);
```

Output:

```text
30
```

The engine executes the instructions, calculates the result, and makes the result available to `console.log()`.

### What does a JavaScript engine do?

The main responsibilities include:

1. **Parsing:** Reading the source code and checking its syntax.
2. **Compilation:** Transforming code into a representation that can be executed.
3. **Execution:** Running the program's instructions.
4. **Optimization:** Making frequently executed code faster where possible.
5. **Memory management:** Managing memory used by JavaScript values and objects, including garbage collection.

The exact internal implementation depends on the engine.

## 4. How Does a JavaScript Engine Execute Code?

Let's understand the process step by step.

Consider this program:

```javascript
let price = 100;
let quantity = 3;

let total = price * quantity;

console.log(total);
```

Output:

```text
300
```

### Simplified execution pipeline

```text
JavaScript Source Code
          |
          v
      Parsing
          |
          v
 Internal Code Representation
          |
          v
 Compilation / Execution
          |
          v
     Optimization
          |
          v
       Program Runs
          |
          v
       Output: 300
```

This is a simplified conceptual diagram. Modern JavaScript engines may interleave interpretation, compilation, execution, and optimization rather than following one rigid sequence.

### Step 1: Parsing

The engine reads the source code and checks whether its syntax is valid.

For example:

```javascript
let age = 21;
console.log(age);
```

This is valid syntax.

But consider:

```javascript
let = age 21;
```

This contains a syntax error, so the engine cannot execute it as a valid program.

### Step 2: Creating an internal representation

The engine transforms the source code into an internal representation that helps it understand the program's structure.

One common representation used in language implementations is an **Abstract Syntax Tree (AST)**.

For example:

```javascript
let result = 10 + 20;
```

Conceptually, the structure represents:

```text
Variable Declaration
        |
        v
   result = ...
        |
        v
      Addition
       /   \
     10     20
```

You do not normally need to create an AST yourself when writing JavaScript.

### Step 3: Compilation and execution

Modern engines commonly use a combination of techniques, including interpreting code and compiling code into machine code.

The engine executes the program's operations, such as:

- Creating variables.
- Performing calculations.
- Calling functions.
- Accessing objects.
- Producing output.

### Step 4: Optimization

If the engine detects that some code runs frequently, it may optimize that code to improve performance.

For example, a function called thousands of times may become a candidate for optimization.

Optimization depends on the engine, the program, and the information available at runtime. Not every function is necessarily optimized.

### Interview definition

**What happens when JavaScript code is executed?**

JavaScript source code is parsed and transformed into an internal representation. The engine executes it using its compilation and execution mechanisms, may optimize frequently executed code, and manages the memory needed by the program.

## 5. What Is a JavaScript Runtime?

### Definition

A **JavaScript runtime** is the broader system that enables JavaScript programs to execute by combining a JavaScript engine with supporting facilities such as APIs, event-loop mechanisms, and other services.

A runtime provides capabilities beyond the engine itself.

For example, a runtime may provide:

- Timers.
- Network communication.
- File access.
- Event handling.
- Access to operating-system services.

The exact capabilities depend on the runtime.

### Engine vs runtime

Think of the engine as the component that executes JavaScript, while the runtime provides the broader environment in which the program operates.

| Feature | JavaScript engine | JavaScript runtime |
|---|---|---|
| Main responsibility | Parses and executes JavaScript | Provides a broader execution environment |
| Executes JavaScript instructions | Yes | Uses an engine to do so |
| Provides environment-specific APIs | Not generally the engine's primary role | Yes |
| Examples | V8, SpiderMonkey | Browser runtime, Node.js runtime |

**Important:** V8 is an engine, not Node.js itself. Node.js uses V8 along with additional components and APIs.

## 6. JavaScript in a Web Browser

A browser provides an environment for running JavaScript associated with web pages.

Examples of browsers include Chrome, Firefox, and Safari.

### What does a browser environment provide?

The browser environment commonly gives JavaScript access to:

- The DOM (Document Object Model).
- Browser events such as clicks and keyboard input.
- Timers such as `setTimeout()`.
- Network APIs such as `fetch()`.
- Browser storage APIs, subject to their rules and permissions.

These facilities allow JavaScript to interact with web pages and browser features.

### Example 1: Changing webpage content

HTML:

```html
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <title>JavaScript Environment</title>
</head>
<body>
  <h1 id="heading">Original Heading</h1>

  <script>
    document.getElementById("heading").textContent =
      "JavaScript Changed This Heading";
  </script>
</body>
</html>
```

When you open this HTML file in a browser, the heading changes to:

```text
JavaScript Changed This Heading
```

### Dry run

1. The browser loads the HTML document.
2. The browser creates the DOM representation of the document.
3. JavaScript executes.
4. `document.getElementById("heading")` finds the element whose ID is `heading`.
5. `.textContent` changes the element's text.
6. The browser displays the updated heading.

### Example 2: Handling a button click

```html
<!DOCTYPE html>
<html lang="en">
<body>
  <p id="message">Waiting for a click...</p>

  <button id="myButton">Click Me</button>

  <script>
    const button = document.getElementById("myButton");
    const message = document.getElementById("message");

    button.addEventListener("click", function () {
      message.textContent = "Button clicked!";
    });
  </script>
</body>
</html>
```

Before clicking:

```text
Waiting for a click...
```

After clicking:

```text
Button clicked!
```

This works because the browser provides the DOM and event-handling APIs.

## 7. What Is Node.js?

### Definition

**Node.js is a JavaScript runtime environment that allows JavaScript to run outside a web browser.**

It is commonly used to build server-side applications, command-line tools, APIs, and development utilities.

Node.js uses the V8 JavaScript engine and provides additional capabilities for interacting with the operating system.

### Why was Node.js useful?

Traditionally, JavaScript was mainly associated with client-side web development in browsers.

Node.js made it practical to use JavaScript for tasks such as:

- Creating web servers.
- Building REST APIs.
- Reading and writing files.
- Building command-line tools.
- Connecting to databases through appropriate libraries.
- Running development tools and build processes.

### Example 1: Run JavaScript using Node.js

Create a file named `app.js`:

```javascript
let name = "Prajwal";
let age = 21;

console.log("Name:", name);
console.log("Age:", age);
```

Run it from your terminal:

```bash
node app.js
```

Output:

```text
Name: Prajwal
Age: 21
```

The values are just example data.

### Example 2: Using Node.js to access a file

Create a file named `readfile.js`:

```javascript
const fs = require("node:fs");

const content = fs.readFileSync("notes.txt", "utf8");

console.log(content);
```

Create a file named `notes.txt` in the same directory:

```text
I am learning JavaScript.
```

Run:

```bash
node readfile.js
```

Output:

```text
I am learning JavaScript.
```

Here, `fs` is a Node.js module that provides file-system functionality.

**Important:** `require("node:fs")` is Node.js-specific. It is not available as a standard browser global.

The example also assumes `notes.txt` exists in the working directory from which you run the command. Otherwise, reading the file will fail.

## 8. Browser vs Node.js

Both environments execute JavaScript, but they provide different APIs because they are designed for different tasks.

| Feature | Browser | Node.js |
|---|---|---|
| Main purpose | Run web-page code | Run JavaScript outside the browser |
| JavaScript engine | Depends on the browser | V8 |
| DOM access | Normally available for web-page scripts | Not built in by default |
| `document` | Available in a normal web-page context | Not available by default |
| `window` | Available in a normal browser page | Not available by default |
| `console.log()` | Supported | Supported |
| File-system access | Restricted and mediated through browser APIs | Available through Node.js APIs |
| Web-page interaction | Yes, through browser APIs | Not directly through a built-in DOM |
| Typical uses | Interactive websites and web applications | Servers, APIs, scripts, command-line tools |

### Important distinction

JavaScript itself defines language features such as variables, functions, arrays, objects, and operators.

The environment provides additional APIs.

For example:

```javascript
let x = 10;
let y = 20;

console.log(x + y);
```

This works in both environments.

However:

```javascript
console.log(document.title);
```

This works in a browser page where `document` is available, but normally fails in Node.js because `document` is not defined.

### Common interview question

**Can JavaScript run without a browser?**

Yes. JavaScript can run in environments such as Node.js, which provide a JavaScript engine and the additional APIs needed to execute programs outside a browser.

## 9. What Is an API in This Context?

### Definition

An **API (Application Programming Interface)** is a defined way for one piece of software to interact with another component or service.

In JavaScript, APIs let your code use capabilities provided by its environment.

Examples:

| API | What it lets you do |
|---|---|
| DOM API | Read and modify webpage elements |
| Timer APIs | Schedule callbacks |
| Fetch API | Make network requests |
| Node.js file-system API | Read and write files |
| Console API | Print diagnostic messages |

### Example

```javascript
console.log("Hello");
```

`console.log()` is provided through the console API.

In a browser, the message generally appears in the developer console. In Node.js, it generally appears in the terminal.

The JavaScript statement is the same, but the place where you see the output depends on the environment.

## 10. What Is the Event Loop?

You will study asynchronous JavaScript in greater depth later. For now, learn the basic idea.

### Definition

The **event loop** is a mechanism used by JavaScript environments to coordinate the execution of queued callbacks and other scheduled work when the JavaScript execution stack is available.

Browsers and Node.js have different event-loop implementations, although both support asynchronous programming.

### Example

```javascript
console.log("First");

setTimeout(function () {
  console.log("Second");
}, 1000);

console.log("Third");
```

Typical output:

```text
First
Third
Second
```

### Dry run

**Step 1:** JavaScript executes:

```javascript
console.log("First");
```

Output:

```text
First
```

**Step 2:** JavaScript schedules the callback through `setTimeout()`.

The program does not need to stop executing the remaining statements while waiting for the timer.

**Step 3:** JavaScript executes:

```javascript
console.log("Third");
```

Output:

```text
Third
```

**Step 4:** After the timer becomes eligible and the runtime can run the callback, it prints:

```text
Second
```

The delay of `1000` milliseconds is a minimum scheduling delay, not a guarantee that the callback will execute at exactly one second.

### Final output

```text
First
Third
Second
```

### Is JavaScript single-threaded?

JavaScript code in a typical execution context runs on a single main thread, but the complete environment may perform other work using browser services, operating-system facilities, or worker threads.

The event loop helps coordinate asynchronous operations. It does not mean every operation is performed on the same thread.

You will learn the call stack, task queues, microtasks, promises, and asynchronous execution in a later module.

## 11. How to Set Up a JavaScript Execution Environment

There are two convenient ways to begin.

### Method A: Use a browser

1. Open a browser such as Chrome.
2. Open Developer Tools.
3. Select the **Console** tab.
4. Type:

```javascript
console.log("My first browser JavaScript program!");
```

Output:

```text
My first browser JavaScript program!
```

This is useful for experimenting with JavaScript and testing small snippets.

### Method B: Use Node.js

1. Install Node.js from the official website: https://nodejs.org/
2. Open a terminal.
3. Check the installation:

```bash
node --version
```

The command should print the installed Node.js version.

4. Check npm:

```bash
npm --version
```

`npm` is the Node.js package manager commonly used to install and manage JavaScript packages.

5. Create a file named `hello.js`:

```javascript
console.log("My first Node.js program!");
```

6. Run:

```bash
node hello.js
```

Output:

```text
My first Node.js program!
```

### Which method should a beginner use?

- Use the **browser console** to experiment with JavaScript and browser APIs.
- Use **Node.js** to execute `.js` files, build command-line programs, and learn server-side JavaScript.
- You can learn the core JavaScript language using either environment.

## 12. Practical Example: One Program, Two Environments

Consider this code:

```javascript
const message = "JavaScript is running!";

console.log(message);
```

### In a browser

You can run the code in the browser console.

Output appears in the developer console:

```text
JavaScript is running!
```

### In Node.js

Save the same code in `message.js` and run:

```bash
node message.js
```

Output appears in the terminal:

```text
JavaScript is running!
```

### What did we learn?

The same JavaScript language syntax can run in multiple environments.

Now consider:

```javascript
console.log(typeof window);
```

In a typical browser page:

```text
object
```

In Node.js:

```text
undefined
```

This is because `window` is a browser-specific global, not a standard global in Node.js.

The exact value of `typeof window` in the browser reflects the usual web-page environment; special execution contexts can differ.

## 13. Common Mistakes

### Mistake 1: Thinking JavaScript and Node.js are the same thing

Incorrect:

> Node.js is the JavaScript language.

Correct:

> JavaScript is a programming language. Node.js is a runtime that executes JavaScript outside a browser.

### Mistake 2: Thinking V8 is the browser

Incorrect:

> V8 is Google Chrome.

Correct:

> V8 is the JavaScript engine used by Chrome and Node.js. Chrome and Node.js provide additional functionality around the engine.

### Mistake 3: Assuming `document` works everywhere

Incorrect:

```javascript
console.log(document.title);
```

This normally works in a browser page, but not in a standard Node.js script.

### Mistake 4: Assuming `console.log()` prints to the same place

The statement is supported in both environments, but its output generally appears in the browser developer console or the Node.js terminal, respectively.

### Mistake 5: Thinking JavaScript always compiles in one fixed way

Modern engines can combine interpretation, compilation, and optimization. Avoid assuming that every JavaScript program follows one rigid execution pipeline.

### Mistake 6: Thinking asynchronous timers interrupt running code

A timer callback normally runs when it is eligible and the JavaScript execution context can process it. A long-running synchronous operation can delay the callback.

## 16. Interview and Viva Questions

### Q1. What is a JavaScript engine?

A JavaScript engine is software that parses JavaScript source code and executes it. It may also optimize code and manage memory.

### Q2. Name three JavaScript engines.

V8, SpiderMonkey, and JavaScriptCore.

### Q3. What is a JavaScript runtime?

A JavaScript runtime is the broader execution system that combines an engine with supporting facilities and APIs for running JavaScript programs.

### Q4. What is Node.js?

Node.js is a JavaScript runtime environment that uses V8 and provides APIs for running JavaScript outside a web browser.

### Q5. What is the difference between an engine and a runtime?

An engine executes JavaScript code. A runtime provides the wider environment, including the engine and supporting APIs or services.

### Q6. Can JavaScript run without a browser?

Yes. It can run in Node.js and other environments that embed a JavaScript engine.

### Q7. Why does `document` work in a browser but not normally in Node.js?

The browser provides the DOM and exposes `document` to ordinary web-page scripts. Node.js does not provide a browser DOM by default.

### Q8. What is V8?

V8 is Google's open-source JavaScript and WebAssembly engine. It is used by Chrome and Node.js.

### Q9. What is the event loop?

The event loop coordinates the processing of scheduled callbacks and other work in an asynchronous JavaScript environment.

### Q10. Is JavaScript single-threaded?

JavaScript execution in a typical main context runs on one thread. However, its environment can perform other work concurrently and may support workers or worker threads.

### Q11. What is the difference between browser JavaScript and Node.js?

Both execute JavaScript, but browsers provide APIs for webpages and browser features, while Node.js provides APIs for tasks such as file access, servers, and operating-system interaction.

### Q12. What happens when a syntax error occurs?

The engine reports a syntax error. Code containing the invalid syntax cannot be executed as a valid program, although error handling and execution details can depend on where the error occurs.
