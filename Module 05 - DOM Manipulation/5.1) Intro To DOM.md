## 2. What Is the DOM?

### Definition

The **Document Object Model (DOM)** is a programming interface that represents an HTML or XML document as a structured tree of objects, allowing programs such as JavaScript to access and modify the document's structure, content, and attributes.

Let's understand the definition piece by piece.

### A. Document

A document is the web page loaded by the browser.

For example:

```html
<!DOCTYPE html>
<html>
<head>
    <title>My Website</title>
</head>
<body>
    <h1>Hello World</h1>
    <p>Welcome to JavaScript.</p>
</body>
</html>
```

The browser loads this HTML document and creates a representation of it that JavaScript can work with.

### B. Object Model

The browser represents parts of the document as objects.

For example:

- The document itself is represented by a `document` object.
- An HTML heading is represented by an element object.
- A paragraph is represented by an element object.
- The text inside the paragraph is represented by a text node.

JavaScript can access these objects through browser-provided APIs.

### C. Why Is the DOM Needed?

HTML describes the initial structure of a web page, but modern websites need to change while users interact with them.

Consider an online shopping website:

- The user clicks **Add to Cart**.
- The cart count increases.
- The total price changes.
- A confirmation message appears.

JavaScript can perform these updates by interacting with the DOM.

Without DOM APIs, JavaScript running in a browser would not have this standard interface for manipulating the page's document structure.

## 3. How Does the DOM Work?

A browser generally follows this process when loading a web page:

1. The browser receives or reads the HTML.
2. The HTML parser processes the markup.
3. The browser constructs a DOM tree representing the document.
4. CSS is parsed into CSS-related structures, including the CSSOM.
5. The browser combines relevant document and style information to calculate layout and render the page.
6. JavaScript can use DOM APIs to inspect or modify the document.

This is a simplified model. Real browsers may interleave parsing, script execution, style calculations, and rendering.

### Example HTML

```html
<!DOCTYPE html>
<html>
<body>
    <h1>Hello</h1>
    <p>Learn JavaScript</p>
</body>
</html>
```

Conceptually, the DOM tree looks like this:

```text
document
   |
   └── html
       |
       └── body
           |
           ├── h1
           |   |
           |   └── "Hello"
           |
           └── p
               |
               └── "Learn JavaScript"
```

The actual DOM also contains nodes associated with other markup, such as the document type, and may contain whitespace text nodes between elements.

### Important Observation

The browser does not simply treat the entire HTML page as one string.

It creates a structured representation containing objects and relationships.

JavaScript can then locate a particular object and change it without rewriting the entire document.

## 4. HTML vs DOM vs JavaScript

These three concepts are related but different.

| Concept | Meaning | Responsibility |
|---|---|---|
| HTML | A markup language | Defines the initial document structure and content |
| DOM | An object representation of a document | Exposes document structure and relationships through APIs |
| JavaScript | A programming language | Implements logic and can interact with the DOM |
| CSS | A style sheet language | Describes the presentation of document elements |
| CSSOM | An object representation of CSS rules and stylesheets | Makes CSS rules available to browser rendering systems and APIs |

### Practical Example

HTML:

```html
<h1 id="heading">Welcome</h1>
```

JavaScript:

```javascript
const heading = document.getElementById("heading");

heading.textContent = "Welcome to JavaScript!";
```

Result displayed on the page:

```text
Welcome to JavaScript!
```

What happened?

1. HTML defined a heading with the initial text `Welcome`.
2. The browser created a DOM representation containing that heading.
3. JavaScript located the heading through the DOM.
4. JavaScript changed the heading's text.
5. The browser updated the displayed page.

**Key point:** JavaScript changed the live DOM. It did not rewrite the original HTML file on your computer.

## 5. Understanding the DOM Tree

The DOM is organized as a tree of nodes.

A tree structure allows the browser and JavaScript to understand the relationships between different parts of a document.

Consider:

```html
<body>
    <div>
        <h1>My Website</h1>
        <p>Welcome!</p>
    </div>
</body>
```

The simplified tree is:

```text
document
   |
   └── html
       |
       └── body
           |
           └── div
               |
               ├── h1
               |   |
               |   └── "My Website"
               |
               └── p
                   |
                   └── "Welcome!"
```

### 5.1 Root Node

The `document` is the entry point for working with the loaded HTML document.

Example:

```javascript
console.log(document);
```

This logs the current document object in a browser's developer console.

### 5.2 Parent Node

A parent node directly contains another node.

In our example:

- `body` is the parent element of `div`.
- `div` is the parent element of `h1`.
- `div` is the parent element of `p`.

Example:

```javascript
const heading = document.querySelector("h1");

console.log(heading.parentElement);
```

Expected result: the `div` element containing the heading.

### 5.3 Child Nodes

A child node is directly contained by another node.

In the example, the `div` contains the `h1` element, text between the elements, and the `p` element.

Example:

```javascript
const container = document.querySelector("div");

console.log(container.childNodes);
```

The result is a `NodeList` that can include:

- Whitespace text nodes created from line breaks and indentation.
- The `h1` element.
- The text node between the elements.
- The `p` element.

To select only direct child **elements**, use:

```javascript
console.log(container.children);
```

This returns an `HTMLCollection` of the `h1` and `p` elements.

### 5.4 Sibling Nodes

Siblings share the same parent.

In our example, `h1` and `p` are sibling elements because both belong to the same `div`.

Example:

```javascript
const heading = document.querySelector("h1");

console.log(heading.nextElementSibling);
```

Expected result:

```html
<p>Welcome!</p>
```

The `nextElementSibling` property ignores whitespace text nodes and returns the next element sibling.

## 6. Nodes and Elements Are Not Exactly the Same

This is an important distinction for interviews and practical coding.

### What Is a Node?

A node is a general object in the DOM tree.

Different kinds of nodes represent different parts of a document.

Common node types include:

| Node type | Example | `nodeType` |
|---|---|---:|
| Document | The `document` object | 9 |
| Element | An HTML `div` element | 1 |
| Text | Text inside an element | 3 |
| Comment | `<!-- comment -->` | 8 |
| Document type | `<!DOCTYPE html>` | 10 |

### What Is an Element?

An element is a specific kind of node representing a markup element, such as:

```html
<div></div>
<p></p>
<button></button>
```

Every element is a node, but not every node is an element.

### Example

HTML:

```html
<div id="box">
    Hello
    <p>JavaScript</p>
</div>
```

JavaScript:

```javascript
const box = document.getElementById("box");

console.log(box.nodeType);
console.log(box.firstChild.nodeType);
console.log(box.firstElementChild.nodeType);
```

Expected output:

```text
1
3
1
```

Explanation:

1. `box.nodeType` is `1` because `box` is an element.
2. `box.firstChild` is the whitespace text node immediately after the opening `div` tag, so its type is `3`.
3. `box.firstElementChild` selects the first child element, which is the `p` element, so its type is `1`.

### Important Comparison

| Property | What it returns |
|---|---|
| `childNodes` | All child nodes, including text and comment nodes |
| `children` | Direct child elements only |
| `firstChild` | The first child node, which may be whitespace |
| `firstElementChild` | The first child element |
| `nextSibling` | The next sibling node, which may be text |
| `nextElementSibling` | The next sibling element |

**Practical rule:** When you want to navigate between HTML elements, properties such as `children`, `firstElementChild`, and `nextElementSibling` are often easier to use.

## 7. How Does JavaScript Access the DOM?

In a browser, JavaScript can access the current document through the global `document` object.

For example:

```javascript
console.log(document.title);
console.log(document.URL);
console.log(document.body);
```

These statements display:

- The current document's title.
- The document's URL.
- The document's body element.

The `document` object provides methods and properties for finding, creating, inspecting, and modifying document nodes.

We'll study element-selection methods in detail in Topic 5.2.

For now, remember this relationship:

```text
JavaScript
    |
    v
document object
    |
    v
DOM elements
    |
    v
Read or modify the page
```

### A Basic Runnable Example

Save this as `dom-introduction.html` and open it in a browser.

```html
<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>DOM Introduction</title>
</head>
<body>
    <h1 id="heading">Hello World</h1>

    <p id="description">I am learning the DOM.</p>

    <script>
        console.log(document.title);

        const heading = document.getElementById("heading");

        console.log(heading.textContent);

        heading.textContent = "Welcome to JavaScript";

        console.log(heading.textContent);
    </script>
</body>
</html>
```

### Expected Console Output

```text
DOM Introduction
Hello World
Welcome to JavaScript
```

The page displays:

```text
Welcome to JavaScript

I am learning the DOM.
```

### Dry Run

| Step | Statement | What happens |
|---|---|---|
| 1 | `console.log(document.title)` | Logs `DOM Introduction` |
| 2 | `document.getElementById("heading")` | Finds the heading element |
| 3 | `console.log(heading.textContent)` | Logs `Hello World` |
| 4 | `heading.textContent = "Welcome to JavaScript"` | Changes the heading's text |
| 5 | `console.log(heading.textContent)` | Logs the new text |

Notice that the `heading` variable refers to the actual DOM element. After changing its `textContent`, the same element contains the updated text.

### Why Does the Script Work?

The browser processes the document from top to bottom in this example. The heading is parsed before the script runs, so the element exists when JavaScript searches for it.

If a script tries to select an element before that element has been parsed, the selection may return `null`.

We'll explore script placement and reliable DOM initialization as we progress.

## 8. Practical Uses of the DOM

The DOM is fundamental to interactive browser applications.

### A. Updating Text

```javascript
message.textContent = "Login successful!";
```

Use case: Displaying confirmation messages after a user submits a form.

### B. Updating a Counter

```javascript
counter.textContent = Number(counter.textContent) + 1;
```

Use case: Increasing a quantity counter when a user adds a product to a cart.

This simple example assumes the existing text is a valid number.

### C. Showing and Hiding Content

JavaScript can add or remove CSS classes that control whether content is displayed.

Use case: Opening menus, accordions, modal dialogs, and dropdowns.

### D. Building Dynamic Lists

JavaScript can create DOM elements from arrays of data.

Use case: Displaying products, search results, comments, and task lists.

### E. Reading User Input

JavaScript can read the value of an input element.

Use case: Validating an email address before submitting a registration form.

### F. Updating API Results

When an application receives data from a server, JavaScript can create or update DOM elements to display the results.

Use case: Displaying weather information, product listings, and dashboard statistics.

## 9. Common Mistakes

### Mistake 1: Confusing HTML with the DOM

HTML is markup used to define the document. The DOM is the browser's object representation of the document.

Changing the DOM does not automatically rewrite the source HTML file saved on your computer.

### Mistake 2: Assuming Every Node Is an Element

Incorrect assumption:

```javascript
const first = container.firstChild;
```

A beginner may assume `first` is always an HTML element.

However, whitespace can create a text node, making `first` a text node instead.

When you need the first child element, use:

```javascript
const first = container.firstElementChild;
```

### Mistake 3: Running JavaScript Before the Element Exists

Example:

```html
<script>
    const heading = document.getElementById("heading");
    console.log(heading.textContent);
</script>

<h1 id="heading">Hello</h1>
```

The script runs before the heading is parsed. Therefore, the lookup returns `null`, and accessing `textContent` throws a `TypeError`.

One solution is to place the script after the element:

```html
<h1 id="heading">Hello</h1>

<script>
    const heading = document.getElementById("heading");
    console.log(heading.textContent);
</script>
```

Another common solution is to use a deferred external script:

```html
<script src="script.js" defer></script>
```

With a normal external classic script using `defer`, the browser executes it after the document has been parsed.

### Mistake 4: Using `innerHTML` When Plain Text Is Enough

If you want to display user-provided text, prefer:

```javascript
message.textContent = userInput;
```

Avoid inserting untrusted user input through `innerHTML`, because it can introduce cross-site scripting (XSS) vulnerabilities.

### Mistake 5: Assuming DOM Changes Persist in the Original File

If JavaScript changes a heading from `Hello` to `Welcome`, the change applies to the live document in the browser.

Refreshing the page normally reloads the original page content and runs its scripts again. To persist user data across reloads, you need an appropriate storage or server-side solution.

## 12. Interview Questions and Answers

### Q1. What is the DOM?

**Answer:** The Document Object Model is a programming interface that represents an HTML or XML document as a tree of objects. It allows JavaScript to access and manipulate the document's structure, content, and attributes.

### Q2. Is the DOM part of JavaScript?

**Answer:** No. The DOM is a web platform API, primarily provided by browsers. JavaScript is a programming language that can use that API. Other languages can also interact with DOM implementations.

### Q3. What is a DOM tree?

**Answer:** A DOM tree is the hierarchical representation of a document, where nodes are connected through parent-child and sibling relationships.

### Q4. What is the difference between a node and an element?

**Answer:** A node is a general unit in the DOM tree. An element is a node representing an HTML or XML element. Text nodes and comment nodes are nodes but are not elements.

### Q5. What is the purpose of the `document` object?

**Answer:** The `document` object represents the loaded document and provides methods and properties to access and manipulate its contents.

### Q6. Does JavaScript directly modify HTML?

**Answer:** JavaScript can modify the live DOM representation of the HTML document. Those changes generally do not rewrite the original HTML file stored on disk.

### Q7. What happens when JavaScript accesses an element that does not exist?

**Answer:** Methods such as `getElementById()` return `null` when they cannot find a matching element. Attempting to access a property on that `null` value can throw a `TypeError`.

### Q8. What is the difference between `children` and `childNodes`?

**Answer:** `children` contains direct child elements only, while `childNodes` contains all direct child nodes, including text and comment nodes.

### Q9. Why is the DOM important in web development?

**Answer:** It allows browser applications to update page content, respond to user interactions, display dynamic data, validate forms, and create interactive interfaces without requiring a full page reload for every change.

### Q10. Can JavaScript run without the DOM?

**Answer:** Yes. JavaScript can run in environments such as Node.js that do not provide a browser DOM by default. The language itself does not require the DOM.

## 13. Quick Revision Notes

- **DOM:** Document Object Model.
- **Purpose:** Provides a structured representation of a document that programs can access and modify.
- **HTML:** Defines the initial document structure and content.
- **JavaScript:** Implements logic and can manipulate the DOM.
- **Document object:** Entry point for working with the loaded document.
- **DOM tree:** Hierarchical structure of document nodes.
- **Node:** General unit in the DOM tree.
- **Element:** Node representing an HTML or XML element.
- **`children`:** Direct child elements.
- **`childNodes`:** All direct child nodes.
- **`textContent`:** Reads or updates text content.
- **`getElementById()`:** Finds an element by its ID.
- **`null`:** Common result when an element lookup fails.
- **`defer`:** Allows an external classic script to execute after HTML parsing.
