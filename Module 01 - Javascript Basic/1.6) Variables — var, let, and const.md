## 2. What Is a Variable?

### Definition

A **variable is a named identifier that refers to a value or holds a binding to a value that a program can access and use.**

In simple words, a variable gives a name to information that your program needs to work with.

### Real-life example

Imagine a box labelled `age`.

The box currently contains the value `21`.

```text
       Variable
      +---------+
      |  age    |
      +---------+
      |   21    |
      +---------+
```

In JavaScript:

```javascript
let age = 21;

console.log(age);
```

Output:

```text
21
```

Here:

- `let` is the declaration keyword.
- `age` is the variable's identifier.
- `=` is the assignment operator.
- `21` is the value assigned to the variable.
- `console.log(age)` accesses and displays its value.

### Why do we need variables?

Without variables, we would repeatedly write values directly into our programs.

For example:

```javascript
console.log(500 * 3);
console.log(500 * 5);
console.log(500 * 10);
```

Here, the price `500` is repeated.

Using a variable makes the program easier to maintain:

```javascript
const price = 500;

console.log(price * 3);
console.log(price * 5);
console.log(price * 10);
```

Output:

```text
1500
2500
5000
```

If the price changes, you can update the value in one place.

## 3. Variable Declaration, Initialization, and Reassignment

These three terms are important for interviews and practical programming.

### 3.1 Declaration

**Declaration means introducing a variable binding into the program.**

Example:

```javascript
let age;
```

The variable `age` has been declared, but no explicit value has been assigned to it.

Because this is a `let` declaration without an initializer, its value is `undefined`.

```javascript
let age;

console.log(age);
```

Output:

```text
undefined
```

### 3.2 Initialization

**Initialization means giving a variable its initial value.**

Example:

```javascript
let age = 21;
```

The variable is declared and initialized in the same statement.

```text
Declaration + Initialization

let age = 21;
    |      |
    |      +---- Initial value
    +----------- Variable identifier
```

### 3.3 Reassignment

**Reassignment means assigning a new value to an already declared variable.**

Example:

```javascript
let age = 21;

age = 22;

console.log(age);
```

Output:

```text
22
```

Dry run:

| Step | Operation | Value of `age` |
|---|---|---:|
| 1 | `let age = 21;` | 21 |
| 2 | `age = 22;` | 22 |
| 3 | `console.log(age);` | 22 |

The old value is replaced by the new value in the variable binding.

### Remember the difference

| Term | Meaning | Example |
|---|---|---|
| Declaration | Introduce a variable | `let score;` |
| Initialization | Give its initial value | `let score = 10;` |
| Reassignment | Change its existing value | `score = 20;` |

Technically, `let score = 10;` declares and initializes the variable in one statement.

## 4. The Three Variable Declaration Keywords

JavaScript provides three commonly used variable declaration keywords:

- `var`
- `let`
- `const`

All three can be used to declare variables, but their rules differ.

### Example

```javascript
var name = "Aarav";
let age = 21;
const country = "India";

console.log(name);
console.log(age);
console.log(country);
```

Output:

```text
Aarav
21
India
```

The differences become important when you try to change values, redeclare variables, or access them from different scopes.

---

## 5. Understanding `var`

### Definition

**`var` is a JavaScript keyword used to declare variables that are function-scoped or, when declared outside a function, scoped to the relevant global execution context.**

`var` is the older variable declaration mechanism in JavaScript.

### 5.1 Declaring a variable with `var`

```javascript
var age = 21;

console.log(age);
```

Output:

```text
21
```

### 5.2 Reassigning a `var` variable

A `var` variable can be reassigned.

```javascript
var age = 21;

age = 22;

console.log(age);
```

Output:

```text
22
```

### 5.3 Redeclaring a `var` variable

Within the same scope, `var` allows the same variable to be declared more than once.

```javascript
var age = 21;
var age = 25;

console.log(age);
```

Output:

```text
25
```

The second declaration does not create a separate local `age` variable in that scope. The assignment updates the existing binding.

Although this is allowed, accidental redeclaration can make programs harder to understand.

### 5.4 `var` is not block-scoped

Consider:

```javascript
if (true) {
    var message = "Hello";
}

console.log(message);
```

Output:

```text
Hello
```

Why does this work?

The `if` statement creates a block, but `var` is not limited to that block. Since the declaration is not inside a function, the variable is available in the surrounding execution context.

### Dry run

```text
1. Enter the if block.
2. Declare message using var.
3. Assign "Hello" to message.
4. Leave the if block.
5. Print message.
6. Output: Hello
```

### 5.5 `var` inside a function

```javascript
function greet() {
    var message = "Hello from function";
    console.log(message);
}

greet();
```

Output:

```text
Hello from function
```

Now try accessing the variable outside the function:

```javascript
function greet() {
    var message = "Hello from function";
}

greet();

console.log(message);
```

This produces a `ReferenceError` because the local `message` binding is not available outside the function.

### Important rules of `var`

- Can be reassigned.
- Can be redeclared in the same scope.
- Is function-scoped rather than block-scoped.
- Is initialized to `undefined` when its declaration is processed during the applicable scope's setup.
- Can be accessed before its declaration statement in some circumstances because of hoisting, but its value may be `undefined`.

## 6. Understanding `let`

### Definition

**`let` is a JavaScript keyword used to declare a block-scoped variable that can be reassigned.**

`let` was introduced in ECMAScript 2015 (ES6).

### 6.1 Declaring a variable

```javascript
let marks = 85;

console.log(marks);
```

Output:

```text
85
```

### 6.2 Reassigning a variable

```javascript
let marks = 85;

marks = 95;

console.log(marks);
```

Output:

```text
95
```

The variable can hold a different value later.

### 6.3 Redeclaring with `let`

Redeclaring a `let` variable in the same scope is not allowed.

Incorrect:

```javascript
let age = 21;
let age = 25;
```

This causes a `SyntaxError` when the declarations occur in the same scope.

Correct:

```javascript
let age = 21;

age = 25;

console.log(age);
```

Output:

```text
25
```

Remember: reassignment is allowed, but redeclaration in the same scope is not.

### 6.4 `let` is block-scoped

A block is generally a group of statements enclosed in curly braces `{ }`.

Example:

```javascript
if (true) {
    let message = "Hello";
    console.log(message);
}
```

Output:

```text
Hello
```

The variable exists within the block where it is declared.

Now consider:

```javascript
if (true) {
    let message = "Hello";
}

console.log(message);
```

This produces a `ReferenceError` because `message` is not available outside the block.

### Scope diagram

```text
Outside block
|
|  message is NOT accessible here
|
+---- if (true) { ----------------+
|                                 |
|  let message = "Hello";         |
|                                 |
|  message IS accessible here     |
|                                 |
+---------------------------------+
|
|  message is NOT accessible here
```

### 6.5 A variable can be declared without an initial value

```javascript
let result;

console.log(result);

result = 100;

console.log(result);
```

Output:

```text
undefined
100
```

The declaration initializes the binding to `undefined`. The later assignment changes its value to `100`.

### Important rules of `let`

- Can be reassigned.
- Cannot be redeclared in the same scope.
- Is block-scoped.
- Cannot be accessed before its declaration is initialized.
- Is subject to the Temporal Dead Zone.

We will examine hoisting and the TDZ shortly.

## 7. Understanding `const`

### Definition

**`const` is a JavaScript keyword used to declare a block-scoped variable binding that must be initialized when declared and cannot later be reassigned.**

`const` was introduced in ES6.

### 7.1 Declaring a constant

```javascript
const country = "India";

console.log(country);
```

Output:

```text
India
```

### 7.2 Reassignment is not allowed

```javascript
const country = "India";

country = "Japan";

console.log(country);
```

This produces a `TypeError` because the existing `const` binding cannot be reassigned.

Correct approach: choose a different declaration keyword if the binding itself must change.

```javascript
let country = "India";

country = "Japan";

console.log(country);
```

Output:

```text
Japan
```

### 7.3 Initialization is required

Incorrect:

```javascript
const age;
```

This causes a `SyntaxError` because a `const` declaration must have an initializer.

Correct:

```javascript
const age = 21;

console.log(age);
```

Output:

```text
21
```

### 7.4 Redeclaration is not allowed in the same scope

Incorrect:

```javascript
const age = 21;
const age = 25;
```

This causes a `SyntaxError` when both declarations are in the same scope.

### 7.5 `const` is block-scoped

```javascript
if (true) {
    const country = "India";
    console.log(country);
}
```

Output:

```text
India
```

Trying to access `country` outside the block produces a `ReferenceError`.

### 7.6 Important: `const` does not make objects immutable

This is one of the most important concepts about `const`.

Consider:

```javascript
const student = {
    name: "Aarav",
    marks: 85
};

student.marks = 95;

console.log(student.marks);
```

Output:

```text
95
```

This works because the `student` binding still refers to the same object. We changed one of the object's properties, not the binding itself.

However, this is not allowed:

```javascript
const student = {
    name: "Aarav"
};

student = {
    name: "Diya"
};
```

This causes a `TypeError` because it attempts to reassign the `student` binding to a different object.

### Visual explanation

Initially:

```text
student
   |
   v
+----------------+
| name: "Aarav"  |
| marks: 85      |
+----------------+
```

After:

```javascript
student.marks = 95;
```

The same object has a new property value:

```text
student
   |
   v
+----------------+
| name: "Aarav"  |
| marks: 95      |
+----------------+
```

The binding still refers to the same object.

### Arrays behave similarly

```javascript
const numbers = [10, 20, 30];

numbers.push(40);

console.log(numbers);
```

Output:

```text
[10, 20, 30, 40]
```

But this is not allowed:

```javascript
const numbers = [10, 20, 30];

numbers = [40, 50, 60];
```

The array can be modified, but the `const` binding cannot be reassigned.

### Important rules of `const`

- Must be initialized when declared.
- Cannot be reassigned.
- Cannot be redeclared in the same scope.
- Is block-scoped.
- Can refer to an object or array whose contents are later modified.
- Is subject to the Temporal Dead Zone.

## 8. Comparison: `var` vs `let` vs `const`

This table is essential for interviews.

| Feature | `var` | `let` | `const` |
|---|---|---|---|
| Can be reassigned? | Yes | Yes | No |
| Can be redeclared in the same scope? | Yes | No | No |
| Scope | Function or global execution context | Block | Block |
| Must be initialized at declaration? | No | No | Yes |
| Initial value when declared without an initializer | `undefined` | `undefined` | Not permitted |
| Hoisted? | Yes | Yes | Yes |
| Can be accessed before declaration initialization? | Sometimes; commonly `undefined` | No | No |
| Temporal Dead Zone? | No, not in the `let`/`const` sense | Yes | Yes |
| Recommended for ordinary modern code? | Usually avoid for new declarations | Yes, when reassignment is needed | Yes, when reassignment is not needed |

### Practical rule

Use `const` by default when you do not need to reassign a binding.

Use `let` when you need to assign a different value later.

Avoid `var` in most new code unless you specifically need to understand or work with its legacy behavior.

## 9. What Is Scope?

### Definition

**Scope determines where a variable or identifier can be accessed in a program.**

In JavaScript, three important concepts are global scope, function scope, and block scope.

### 9.1 Global scope

A variable declared outside functions and blocks may be available throughout the relevant global scope.

Example:

```javascript
const course = "JavaScript";

function showCourse() {
    console.log(course);
}

showCourse();
console.log(course);
```

Output:

```text
JavaScript
JavaScript
```

The function can access the outer `course` binding because of lexical scope.

Note: global bindings behave differently depending on whether code runs as a classic browser script, an ES module, or in Node.js. A top-level declaration is not always a property of `globalThis`.

### 9.2 Function scope

A function-scoped variable is available within the function in which it is declared.

Example:

```javascript
function calculate() {
    var total = 100;
    console.log(total);
}

calculate();
```

Output:

```text
100
```

The variable `total` is local to the function.

Trying to access it outside the function causes a `ReferenceError`.

### 9.3 Block scope

A block-scoped variable declared with `let` or `const` is accessible only within its enclosing block.

Example:

```javascript
{
    let score = 90;
    const grade = "A";

    console.log(score);
    console.log(grade);
}
```

Output:

```text
90
A
```

Neither `score` nor `grade` is accessible outside that block.

### Compare them

```javascript
{
    var a = 10;
    let b = 20;
    const c = 30;
}

console.log(a); // 10
console.log(b); // ReferenceError if reached
console.log(c); // ReferenceError if reached
```

The first `console.log()` succeeds because `var` is not block-scoped.

The second statement throws an error, so normal execution of this script stops there; the third statement is not reached.

### Why does scope matter?

Scope helps you:

- Avoid naming conflicts.
- Keep temporary variables local.
- Prevent accidental access to unrelated data.
- Organize functions and blocks.
- Make code easier to understand and maintain.

## 10. What Is Hoisting?

### Definition

**Hoisting is the behavior in which JavaScript establishes certain declarations during the setup of a scope before executing the code in that scope.**

Hoisting does not literally mean that JavaScript moves your source-code lines to the top.

Different declarations behave differently.

### 10.1 Hoisting with `var`

Consider:

```javascript
console.log(age);

var age = 21;
```

Output:

```text
undefined
```

Why?

A simplified conceptual model of the declaration is:

```javascript
var age;

console.log(age);

age = 21;
```

This is an explanatory model of the behavior, not a literal rewriting performed on your source file.

The `var` binding exists and is initialized to `undefined` before the assignment runs.

### Step-by-step dry run

| Step | Operation | Value of `age` | Output |
|---|---|---|---|
| 1 | Scope setup creates the `var` binding | `undefined` | — |
| 2 | `console.log(age)` executes | `undefined` | `undefined` |
| 3 | `age = 21` executes | `21` | — |

### 10.2 Hoisting with `let`

Consider:

```javascript
console.log(age);

let age = 21;
```

This throws a `ReferenceError`.

The `let` declaration is established during scope setup, but it cannot be accessed before its initialization is reached.

### 10.3 Hoisting with `const`

Similarly:

```javascript
console.log(country);

const country = "India";
```

This throws a `ReferenceError` because `country` has not yet been initialized.

### Comparison

| Keyword | Binding established during scope setup? | Initial state before declaration is reached | Access before initialization |
|---|---|---|---|
| `var` | Yes | `undefined` | Can succeed with value `undefined` |
| `let` | Yes | Uninitialized | Throws `ReferenceError` |
| `const` | Yes | Uninitialized | Throws `ReferenceError` |

## 11. What Is the Temporal Dead Zone (TDZ)?

### Definition

**The Temporal Dead Zone is the period between entering a scope and initializing a `let` or `const` binding during which that binding cannot be accessed.**

This behavior prevents the variable from being used before its initialization.

### Example

```javascript
{
    // TDZ for message begins when this block is entered.

    // console.log(message); // Would throw ReferenceError

    let message = "Hello";

    console.log(message);
}
```

Output:

```text
Hello
```

The declaration's initialization ends the TDZ for `message`.

### Example that produces an error

```javascript
{
    console.log(message);

    let message = "Hello";
}
```

This throws a `ReferenceError`.

### Visual representation

```text
Enter block
    |
    v
Binding exists but is uninitialized
    |
    |  Temporal Dead Zone
    |
    v
let message = "Hello";
    |
    v
Binding is initialized
    |
    v
message can be accessed
```

### Why does `var` behave differently?

With `var`, the binding is initialized to `undefined` during scope setup. With `let` and `const`, the binding remains uninitialized until its declaration is evaluated.

### Interview definition

The TDZ is the interval during which a lexical binding declared with `let`, `const`, or `class` exists in its scope but cannot be accessed because initialization has not yet occurred.

## 12. Variable Redeclaration and Reassignment

These concepts are frequently confused.

### Example A: `var`

```javascript
var score = 10;
var score = 20;

console.log(score);
```

Output:

```text
20
```

Redeclaration and reassignment are allowed in this case.

### Example B: `let`

```javascript
let score = 10;

score = 20;

console.log(score);
```

Output:

```text
20
```

Reassignment is allowed.

But this is invalid in the same scope:

```javascript
let score = 10;
let score = 20;
```

### Example C: `const`

```javascript
const score = 10;

console.log(score);
```

Output:

```text
10
```

Reassignment is not allowed:

```javascript
const score = 10;

score = 20;
```

This throws a `TypeError`.

### Quick memory trick

- `var`: Can redeclare and reassign.
- `let`: Can reassign, but cannot redeclare in the same scope.
- `const`: Cannot reassign or redeclare in the same scope.

## 13. A Practical Example: Student Marks

Let's use variables to calculate a student's total and percentage.

```javascript
const studentName = "Aarav";

let maths = 85;
let science = 90;
let english = 80;

const total = maths + science + english;
const percentage = (total / 300) * 100;

console.log("Student:", studentName);
console.log("Total:", total);
console.log("Percentage:", percentage + "%");
```

Output:

```text
Student: Aarav
Total: 255
Percentage: 85%
```

### Dry run

Initial values:

```text
studentName = "Aarav"
maths = 85
science = 90
english = 80
```

Calculate total:

```text
total = 85 + 90 + 80
total = 255
```

Calculate percentage:

```text
percentage = (255 / 300) * 100
percentage = 85
```

Print the values.

### Why use `const` and `let` here?

- `studentName` is declared with `const` because this example does not need to reassign the name.
- The marks use `let` because they might be updated later.
- `total` and `percentage` use `const` because they are calculated once in this program.

The choice depends on whether reassignment is needed, not merely on whether the value is a number or string.

## 14. Common Beginner Mistakes

### Mistake 1: Using `const` when you need reassignment

Incorrect:

```javascript
const age = 21;
age = 22;
```

Correct:

```javascript
let age = 21;
age = 22;
```

### Mistake 2: Using `let` twice in the same scope

Incorrect:

```javascript
let name = "Aarav";
let name = "Diya";
```

Correct:

```javascript
let name = "Aarav";
name = "Diya";
```

### Mistake 3: Accessing a `let` variable before initialization

Incorrect:

```javascript
console.log(score);
let score = 100;
```

This throws a `ReferenceError`.

Correct:

```javascript
let score = 100;
console.log(score);
```

### Mistake 4: Assuming `const` makes an object completely unchangeable

Incorrect assumption:

> If an object is declared using `const`, none of its properties can change.

Actual behavior:

```javascript
const user = { name: "Aarav" };

user.name = "Diya";

console.log(user.name);
```

Output:

```text
Diya
```

The binding cannot be reassigned, but the object can still be mutable.

### Mistake 5: Assuming `var` is block-scoped

```javascript
if (true) {
    var result = 100;
}

console.log(result);
```

Output:

```text
100
```

`var` does not have the same block-scope behavior as `let` and `const`.

### Mistake 6: Thinking hoisting literally moves every declaration to the top

Hoisting is a useful way to describe observable behavior. It is not a literal source-code movement process, and `var`, `let`, `const`, and function declarations do not all behave identically.

## 17. Interview and Viva Questions

### Q1. What is a variable in JavaScript?

A variable is a named binding used to store or refer to a value so that the program can access and use that value.

### Q2. What are the three variable declaration keywords?

`var`, `let`, and `const`.

### Q3. What is the difference between `var` and `let`?

`var` is function-scoped or global-scoped and permits redeclaration in the same scope. `let` is block-scoped and does not permit redeclaration in the same scope, although it permits reassignment.

### Q4. What is the difference between `let` and `const`?

Both are block-scoped. `let` permits reassignment, whereas `const` does not permit reassignment and requires an initializer.

### Q5. Can we declare a `const` variable without initializing it?

No. A `const` declaration must be initialized when declared.

### Q6. Can we modify an object declared with `const`?

Yes. Its properties can be modified if the object is mutable, but the variable binding cannot be reassigned to another object.

### Q7. What is scope?

Scope determines where an identifier can be accessed in a program.

### Q8. What is function scope?

Function scope means a variable is available within the function in which it is declared, subject to the language's scope rules.

### Q9. What is block scope?

Block scope means a binding is available within its enclosing block. `let` and `const` are block-scoped.

### Q10. What is hoisting?

Hoisting describes how JavaScript establishes declarations during scope setup before executing statements in that scope.

### Q11. What is the Temporal Dead Zone?

The TDZ is the period before a lexical binding is initialized during which the binding cannot be accessed.

### Q12. Can we redeclare a `var` variable?

Yes, redeclaration is allowed within the same scope in which `var` declarations are permitted.

### Q13. Can we redeclare a `let` variable in the same scope?

No. Declaring the same `let` binding again in the same scope produces a `SyntaxError`.

### Q14. Which declaration keyword should be used in modern JavaScript?

Prefer `const` when reassignment is unnecessary and `let` when reassignment is needed. Generally avoid `var` in new code unless its specific behavior is required.

### Q15. What happens when a `let` variable is accessed before initialization?

A `ReferenceError` is thrown because the binding is still in the Temporal Dead Zone.

## 18. Quick Revision Notes

- **Variable:** A named binding used to access a value.
- **Declaration:** Introducing a variable binding.
- **Initialization:** Giving the variable its initial value.
- **Reassignment:** Assigning a new value to an existing binding.
- **`var`:** Function-scoped or global-scoped; can be redeclared and reassigned.
- **`let`:** Block-scoped; can be reassigned but not redeclared in the same scope.
- **`const`:** Block-scoped; must be initialized and cannot be reassigned.
- **Scope:** Determines where an identifier is accessible.
- **Hoisting:** Describes declaration setup before statement execution.
- **TDZ:** The period before a `let` or `const` binding is initialized.
- **Object declared with `const`:** Its binding cannot be reassigned, but its properties may be mutable.

### The easiest rule to remember

```javascript
const country = "India"; // Cannot reassign the binding

let age = 21;            // Can reassign
age = 22;

var oldStyle = "Legacy"; // Older declaration style
```
