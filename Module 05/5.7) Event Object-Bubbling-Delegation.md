# Topic 5.7: Event Objects, Event Bubbling, and Event Delegation in JavaScript

## 1. Introduction

In the previous topic, we learned:

```javascript
button.addEventListener("click", function () {
    console.log("Button clicked!");
});
```

This code tells JavaScript to execute a function when the button is clicked.

But consider this HTML:

```html
<div id="parent">
    <button id="child">Click Me</button>
</div>
```

When the user clicks the button:

- The button receives the click.
- The parent `div` can also receive the same event as it propagates.
- Other ancestor elements can also receive the event.

This behavior is called **event propagation**.

To understand it properly, we first need to understand the Event Object.

---

## 2. What is the Event Object?

### Definition

The Event Object is an object automatically provided to an event listener when an event occurs. It contains information about the event, such as its type, target element, current target, keyboard key, mouse coordinates, and other event-related details.

In simple words:

**The Event Object tells us what happened, where it happened, and provides information about that event.**

### Basic syntax

```javascript
element.addEventListener("click", function (event) {
    // Use event object here
});
```

Here:

- `event` is a parameter of the callback function.
- The browser passes an event object to the callback when the listener runs.
- We can access its properties and methods.

The parameter name does not have to be `event`. It is a normal JavaScript parameter.

For example:

```javascript
button.addEventListener("click", function (e) {
    console.log(e);
});
```

Both `event` and `e` work.

### Example 1: Accessing the Event Object

```html
<!DOCTYPE html>
<html>
<body>

    <button id="myButton">Click Me</button>

    <script>
        const button = document.getElementById("myButton");

        button.addEventListener("click", function (event) {
            console.log(event);
        });
    </script>

</body>
</html>
```

**Expected result:**

When you click the button, the browser console displays a `PointerEvent` object (a kind of `MouseEvent`, which is itself an `Event`).

The object contains properties and methods that describe the click.

---

## 3. Important Properties of the Event Object

The Event Object has many properties. Let's understand the most commonly used ones.

| Property | Meaning |
|---|---|
| `event.type` | Returns the event type |
| `event.target` | Returns the original target of the event |
| `event.currentTarget` | Returns the element whose listener is currently executing |
| `event.eventPhase` | Indicates the current propagation phase |
| `event.bubbles` | Indicates whether the event bubbles |
| `event.cancelable` | Indicates whether its default action can be canceled |
| `event.defaultPrevented` | Indicates whether the default action has been prevented |
| `event.timeStamp` | Returns the time at which the event was created, relative to the relevant time origin |

### 3.1 event.type

It returns the name of the event.

Example:

```html
<button id="myButton">Click Me</button>

<script>
    const button = document.getElementById("myButton");

    button.addEventListener("click", function (event) {
        console.log(event.type);
    });
</script>
```

**Output:**

```text
click
```

If the listener is registered for a `mouseover` event, `event.type` returns:

```text
mouseover
```

### 3.2 event.target

It identifies the original target of the event.

Example:

```html
<div id="parent">
    <button id="child">Click Me</button>
</div>

<script>
    const parent = document.getElementById("parent");

    parent.addEventListener("click", function (event) {
        console.log(event.target);
    });
</script>
```

When the button is clicked, the output refers to the button element.

Why?

Because the button is the element on which the click originally occurred.

Even though the listener is registered on the parent, the original event target is the button.

### 3.3 event.currentTarget

It identifies the element whose event listener is currently executing.

Example:

```html
<div id="parent">
    <button id="child">Click Me</button>
</div>

<script>
    const parent = document.getElementById("parent");

    parent.addEventListener("click", function (event) {
        console.log("Target:", event.target);
        console.log("Current Target:", event.currentTarget);
    });
</script>
```

When the button is clicked:

```text
Target: <button id="child">Click Me</button>
Current Target: <div id="parent">...</div>
```

Why are they different?

- `event.target` is the button where the click originated.
- `event.currentTarget` is the parent whose listener is executing.

### Important: target vs currentTarget

This is one of the most important differences in DOM event handling.

| `event.target` | `event.currentTarget` |
|---|---|
| Original event target | Element whose listener is currently executing |
| Can be a child of the listener element | Is the element on which the current listener was registered |
| Usually remains the same as the event propagates through ancestors | Changes as different listeners execute |
| Useful for identifying what was clicked | Useful for identifying which listener is handling the event |

### Visual understanding

Consider:

```html
<div id="grandparent">
    <div id="parent">
        <button id="child">Click Me</button>
    </div>
</div>
```

Suppose listeners are attached to all three elements:

```javascript
const grandparent = document.getElementById("grandparent");
const parent = document.getElementById("parent");
const child = document.getElementById("child");

grandparent.addEventListener("click", function (event) {
    console.log("Grandparent");
    console.log("Target:", event.target.id);
    console.log("Current:", event.currentTarget.id);
});

parent.addEventListener("click", function (event) {
    console.log("Parent");
    console.log("Target:", event.target.id);
    console.log("Current:", event.currentTarget.id);
});

child.addEventListener("click", function (event) {
    console.log("Child");
    console.log("Target:", event.target.id);
    console.log("Current:", event.currentTarget.id);
});
```

When you click the button, the output during bubbling is:

```text
Child
Target: child
Current: child

Parent
Target: child
Current: parent

Grandparent
Target: child
Current: grandparent
```

Notice:

- `target` remains `child`.
- `currentTarget` changes according to the listener currently executing.

### 3.4 event.bubbles

It tells us whether an event is configured to bubble.

```javascript
button.addEventListener("click", function (event) {
    console.log(event.bubbles);
});
```

For a normal click event:

```text
true
```

Not every event bubbles. For example, `focus` and `blur` do not bubble in the ordinary way. Their bubbling counterparts are `focusin` and `focusout`.

### 3.5 event.cancelable

It tells us whether the event's default action can be canceled.

```javascript
button.addEventListener("click", function (event) {
    console.log(event.cancelable);
});
```

A typical click event is cancelable.

Calling `preventDefault()` only cancels the default action when the event is cancelable and the listener is allowed to cancel it.

### 3.6 event.eventPhase

It tells us which phase of event propagation is currently active.

The values are:

| Constant | Numeric value | Meaning |
|---|---:|---|
| `Event.NONE` | 0 | No event phase is active |
| `Event.CAPTURING_PHASE` | 1 | Capturing phase |
| `Event.AT_TARGET` | 2 | Event is at its target |
| `Event.BUBBLING_PHASE` | 3 | Bubbling phase |

Example:

```javascript
button.addEventListener("click", function (event) {
    console.log(event.eventPhase);
});
```

When the listener runs on the button itself, the value is usually:

```text
2
```

This is because the event is at its target.

## 4. Event Object: Important Methods

The Event Object also provides methods that control event behavior.

The two important methods are:

1. `preventDefault()`
2. `stopPropagation()`

We will understand these separately.

### 4.1 preventDefault()

#### Definition

`preventDefault()` is a method used to prevent the browser's default action associated with an event, provided that the event is cancelable and the listener is not passive.

Example: Preventing a link from navigating.

```html
<a href="https://example.com" id="myLink">
    Visit Website
</a>

<script>
    const link = document.getElementById("myLink");

    link.addEventListener("click", function (event) {
        event.preventDefault();

        console.log("Navigation prevented!");
    });
</script>
```

**Expected result:**

When the link is clicked:

```text
Navigation prevented!
```

The browser does not navigate to the link's destination.

Why?

Normally, clicking an anchor element navigates to its `href`.

But:

```javascript
event.preventDefault();
```

cancels that default action.

### Another example: Preventing form submission

```html
<form id="myForm">
    <input type="text" placeholder="Enter name">

    <button type="submit">Submit</button>
</form>

<script>
    const form = document.getElementById("myForm");

    form.addEventListener("submit", function (event) {
        event.preventDefault();

        console.log("Default form submission prevented!");
    });
</script>
```

The browser's normal form submission is prevented so JavaScript can handle the form.

### Important point

`preventDefault()` does not stop event propagation.

It only prevents the browser's default action.

---

### 4.2 stopPropagation()

#### Definition

`stopPropagation()` is a method used to stop an event from continuing to propagate through the DOM.

In simple words:

It prevents the event from moving to further ancestors or descendants along its propagation path.

Example:

```html
<div id="parent">
    Parent
    <button id="child">Click Me</button>
</div>

<script>
    const parent = document.getElementById("parent");
    const child = document.getElementById("child");

    parent.addEventListener("click", function () {
        console.log("Parent clicked");
    });

    child.addEventListener("click", function (event) {
        console.log("Child clicked");

        event.stopPropagation();
    });
</script>
```

**Output when the button is clicked:**

```text
Child clicked
```

Why is `Parent clicked` not printed?

Normally, the click event bubbles from the button to its parent.

But:

```javascript
event.stopPropagation();
```

stops the event from continuing to the parent.

### Important distinction

`stopPropagation()` does not prevent the browser's default action.

For example, stopping propagation on a link does not automatically prevent navigation.

---

### 4.3 stopImmediatePropagation()

There is another related method:

```javascript
event.stopImmediatePropagation();
```

It stops the event from continuing to propagate and also prevents other listeners on the same target from being invoked after the method is called.

Example:

```html
<button id="myButton">Click Me</button>

<script>
    const button = document.getElementById("myButton");

    button.addEventListener("click", function (event) {
        console.log("First listener");

        event.stopImmediatePropagation();
    });

    button.addEventListener("click", function () {
        console.log("Second listener");
    });
</script>
```

**Output:**

```text
First listener
```

The second listener does not run.

### Comparison of the three methods

| Method | Prevents default browser action? | Stops propagation? | Stops later listeners on same target? |
|---|---|---|---|
| `preventDefault()` | Yes, if cancelable and not passive | No | No |
| `stopPropagation()` | No | Yes | No |
| `stopImmediatePropagation()` | No | Yes | Yes |

Remember this table carefully. It is frequently asked in interviews.

---

## 5. What is Event Propagation?

### Definition

Event propagation is the process through which an event travels through the DOM tree when it occurs on an element.

When a user clicks an element inside nested HTML elements, the event can travel through its ancestors.

Event propagation has three phases:

1. Capturing phase.
2. Target phase.
3. Bubbling phase.

### Example HTML structure

```html
<div id="grandparent">
    <div id="parent">
        <button id="child">Click Me</button>
    </div>
</div>
```

Visual representation:

```text
Grandparent
    |
    Parent
        |
        Child Button
```

Suppose the user clicks the child button.

The event can travel through the following phases.

---

## 6. Event Capturing Phase

### Definition

Event capturing is the phase in which an event travels from the outermost ancestor toward the target element.

In simple words:

**The event moves from parent to child until it reaches the element that was clicked.**

For our example:

```text
Grandparent
    |
    Parent
        |
        Child Button  ← Click happens here
```

During capturing, the direction is:

```text
Grandparent
      ↓
   Parent
      ↓
 Child Button
```

### How to register a capturing listener

By default, `addEventListener()` registers a listener for the bubbling phase (or target phase when the target is reached).

To register for the capturing phase, pass `true` as the third argument or use `{ capture: true }`.

Syntax:

```javascript
element.addEventListener("click", callback, true);
```

Or:

```javascript
element.addEventListener("click", callback, {
    capture: true
});
```

### Example

```html
<div id="grandparent">
    Grandparent

    <div id="parent">
        Parent

        <button id="child">Click Me</button>
    </div>
</div>

<script>
    const grandparent = document.getElementById("grandparent");
    const parent = document.getElementById("parent");
    const child = document.getElementById("child");

    grandparent.addEventListener("click", function () {
        console.log("Grandparent capturing");
    }, true);

    parent.addEventListener("click", function () {
        console.log("Parent capturing");
    }, true);

    child.addEventListener("click", function () {
        console.log("Child target");
    });

</script>
```

**Output when the button is clicked:**

```text
Grandparent capturing
Parent capturing
Child target
```

The capturing listeners run from the outer ancestor toward the target.

---

## 7. Target Phase

### Definition

The target phase is the phase in which the event reaches the actual target element.

For example, if the user clicks a button, that button is the event target.

```text
Grandparent
      |
   Parent
      |
   Button  ← Target phase
```

At the target, listeners registered for both capture and non-capture can run.

Example:

```javascript
button.addEventListener("click", function () {
    console.log("Target - capture listener");
}, true);

button.addEventListener("click", function () {
    console.log("Target - non-capture listener");
});
```

Both listeners can run at the target.

For listeners on the same target, capture listeners are invoked before non-capture listeners.

---

## 8. Event Bubbling Phase

### Definition

Event bubbling is the phase in which an event travels from the target element upward through its ancestors.

In simple words:

**The event moves from child to parent after reaching the target.**

For our example:

```text
Grandparent
      ↑
   Parent
      ↑
 Child Button  ← Click happens here
```

The event travels:

```text
Child Button
      ↑
   Parent
      ↑
Grandparent
```

### Example

```html
<div id="grandparent">
    Grandparent

    <div id="parent">
        Parent

        <button id="child">Click Me</button>
    </div>
</div>

<script>
    const grandparent = document.getElementById("grandparent");
    const parent = document.getElementById("parent");
    const child = document.getElementById("child");

    grandparent.addEventListener("click", function () {
        console.log("Grandparent");
    });

    parent.addEventListener("click", function () {
        console.log("Parent");
    });

    child.addEventListener("click", function () {
        console.log("Child");
    });
</script>
```

**Output when the child button is clicked:**

```text
Child
Parent
Grandparent
```

Why?

Because the default listeners are registered for bubbling, and the event travels from the target toward its ancestors.

---

## 9. Complete Event Propagation Example

Let's combine capturing, target, and bubbling.

### HTML + JavaScript

```html
<!DOCTYPE html>
<html>
<body>

    <div id="grandparent">
        Grandparent

        <div id="parent">
            Parent

            <button id="child">Click Me</button>
        </div>
    </div>

    <script>
        const grandparent = document.getElementById("grandparent");
        const parent = document.getElementById("parent");
        const child = document.getElementById("child");

        // Capturing phase
        grandparent.addEventListener("click", function () {
            console.log("Grandparent - Capturing");
        }, true);

        parent.addEventListener("click", function () {
            console.log("Parent - Capturing");
        }, true);

        // Target phase
        child.addEventListener("click", function () {
            console.log("Child - Target");
        });

        // Bubbling phase
        parent.addEventListener("click", function () {
            console.log("Parent - Bubbling");
        });

        grandparent.addEventListener("click", function () {
            console.log("Grandparent - Bubbling");
        });
    </script>

</body>
</html>
```

### Expected output

When the child button is clicked:

```text
Grandparent - Capturing
Parent - Capturing
Child - Target
Parent - Bubbling
Grandparent - Bubbling
```

### Complete event flow diagram

```text
              CAPTURING PHASE
                     |
                     v
              Grandparent
                     |
                     v
                 Parent
                     |
                     v
              +-------------+
              |   BUTTON    |
              |   TARGET    |
              +-------------+
                     |
                     v
                 Parent
                     |
                     v
              Grandparent
                     |
                     v
              BUBBLING PHASE
```

### Remember the direction

| Phase | Direction |
|---|---|
| Capturing | Parent → Child |
| Target | Event reaches the target |
| Bubbling | Child → Parent |

**Important:** Not every event bubbles. The propagation path and whether an event bubbles depend on the event type. Click events bubble, which makes them useful for event delegation.

## 10. What is Event Delegation?

Now we come to one of the most useful concepts in DOM event handling.

### The problem

Imagine you have a list containing 100 buttons.

```html
<ul>
    <li><button>Delete</button></li>
    <li><button>Delete</button></li>
    <li><button>Delete</button></li>
    <!-- Many more items -->
</ul>
```

One approach is to select every button and attach a click listener to each one.

```javascript
const buttons = document.querySelectorAll("button");

buttons.forEach(function (button) {
    button.addEventListener("click", function () {
        console.log("Delete clicked");
    });
});
```

This works for the buttons that exist when the code runs.

But what happens if new buttons are added later using JavaScript?

The newly created buttons do not automatically receive the listeners attached to the original buttons.

We could attach another listener every time we create a new button, but that adds more work.

**Event delegation provides a better solution.**

### Definition

Event delegation is a technique in which a single event listener is attached to a common parent element to handle events originating from its child elements.

It works by using event propagation, especially event bubbling.

In simple words:

**Instead of attaching listeners to every child, attach one listener to their parent and identify which child triggered the event.**

### How event delegation works

Consider:

```html
<ul id="itemList">
    <li>Item 1</li>
    <li>Item 2</li>
    <li>Item 3</li>
</ul>
```

Instead of attaching a click listener to every `li`, we attach one listener to the `ul`.

```javascript
const itemList = document.getElementById("itemList");

itemList.addEventListener("click", function (event) {
    console.log(event.target);
});
```

When an `li` is clicked:

1. The click occurs on the `li`.
2. The event bubbles upward.
3. The `ul` receives the event.
4. Its listener executes.
5. `event.target` identifies the original element that was clicked.

This is the basic idea behind event delegation.

## 11. Implementing Event Delegation Properly

There is one important detail.

What if the user clicks a nested element inside an `li`?

Consider:

```html
<ul id="itemList">
    <li>
        <span>Item 1</span>
        <button>Delete</button>
    </li>
</ul>
```

If the user clicks the text inside the `span`, then `event.target` will be the `span`, not the `li`.

Therefore, we should identify the correct child element using methods such as `closest()`.

### Using closest()

`closest()` searches for the nearest element that matches a CSS selector, starting with the element itself and moving upward through its ancestors.

Syntax:

```javascript
element.closest("CSS selector");
```

Example:

```html
<ul id="itemList">
    <li class="item">
        <span>Item 1</span>
        <button class="delete">Delete</button>
    </li>
</ul>

<script>
    const itemList = document.getElementById("itemList");

    itemList.addEventListener("click", function (event) {

        const deleteButton = event.target.closest(".delete");

        if (deleteButton) {
            console.log("Delete button clicked");
        }

    });
</script>
```

### Understanding the code

```javascript
const deleteButton = event.target.closest(".delete");
```

This searches from the clicked element upward to find the nearest element with the class `delete`.

```javascript
if (deleteButton) {
```

If such an element is found, the condition is true.

```javascript
console.log("Delete button clicked");
```

The message is printed.

### Why is closest() useful?

Suppose the button contains an icon:

```html
<button class="delete">
    <span>🗑</span>
    Delete
</button>
```

If the user clicks the `span`, the event target is the `span`.

But:

```javascript
event.target.closest(".delete");
```

finds the surrounding button.

This makes event delegation more reliable.

### A safe pattern for delegation

```javascript
const container = document.getElementById("container");

container.addEventListener("click", function (event) {

    if (!(event.target instanceof Element)) {
        return;
    }

    const button = event.target.closest(".delete");

    if (!button || !container.contains(button)) {
        return;
    }

    console.log("Delete clicked");

});
```

Why use `container.contains(button)`?

It confirms that the matched button belongs to the intended container.

This is useful when `closest()` could find a matching element outside the container.

## 12. Complete Practical Project: Dynamic To-Do List Using Event Delegation

Let's build a to-do list where:

- The user can add tasks.
- Every task has a Delete button.
- The user can delete tasks.
- We use only one click listener on the task list.
- Newly created buttons work without registering individual listeners.

### Complete runnable code

```html
<!DOCTYPE html>
<html>
<head>
    <title>Event Delegation To-Do List</title>

    <style>
        body {
            font-family: Arial, sans-serif;
            margin: 40px;
        }

        li {
            margin: 10px 0;
        }

        button {
            margin-left: 10px;
            cursor: pointer;
        }
    </style>
</head>
<body>

    <h1>My To-Do List</h1>

    <input type="text" id="taskInput" placeholder="Enter a task">

    <button id="addButton">Add Task</button>

    <ul id="taskList"></ul>

    <script>
        const taskInput = document.getElementById("taskInput");
        const addButton = document.getElementById("addButton");
        const taskList = document.getElementById("taskList");

        // Add a new task
        addButton.addEventListener("click", function () {

            const taskText = taskInput.value.trim();

            if (taskText === "") {
                alert("Please enter a task");
                return;
            }

            const li = document.createElement("li");

            const span = document.createElement("span");
            span.textContent = taskText;

            const deleteButton = document.createElement("button");
            deleteButton.textContent = "Delete";
            deleteButton.classList.add("delete");

            li.append(span, deleteButton);

            taskList.appendChild(li);

            taskInput.value = "";
        });

        // One listener handles all delete buttons
        taskList.addEventListener("click", function (event) {

            if (!(event.target instanceof Element)) {
                return;
            }

            const deleteButton = event.target.closest(".delete");

            if (!deleteButton || !taskList.contains(deleteButton)) {
                return;
            }

            const task = deleteButton.closest("li");

            if (task) {
                task.remove();
            }
        });
    </script>

</body>
</html>
```

### How the project works

#### Step 1: Select the elements

```javascript
const taskInput = document.getElementById("taskInput");
const addButton = document.getElementById("addButton");
const taskList = document.getElementById("taskList");
```

We select:

- Input field.
- Add button.
- Task list.

#### Step 2: Register the Add Task listener

```javascript
addButton.addEventListener("click", function () {
```

When the Add Task button is clicked, the callback executes.

#### Step 3: Read and validate the input

```javascript
const taskText = taskInput.value.trim();

if (taskText === "") {
    alert("Please enter a task");
    return;
}
```

We get the text entered by the user.

`trim()` removes whitespace from the beginning and end.

If the resulting value is empty, the function stops.

#### Step 4: Create the task elements

```javascript
const li = document.createElement("li");

const span = document.createElement("span");
span.textContent = taskText;

const deleteButton = document.createElement("button");
deleteButton.textContent = "Delete";
deleteButton.classList.add("delete");
```

We create:

- An `li` element.
- A `span` containing the task text.
- A Delete button with the `delete` class.

#### Step 5: Insert the elements

```javascript
li.append(span, deleteButton);

taskList.appendChild(li);
```

The span and button are placed inside the list item.

Then the list item is inserted into the task list.

#### Step 6: Register one listener on the parent

```javascript
taskList.addEventListener("click", function (event) {
```

This listener handles clicks originating from the task list's descendants.

#### Step 7: Identify the Delete button

```javascript
const deleteButton = event.target.closest(".delete");
```

We search for the closest Delete button.

#### Step 8: Confirm it belongs to our list

```javascript
if (!deleteButton || !taskList.contains(deleteButton)) {
    return;
}
```

If no matching Delete button exists inside our list, we stop.

#### Step 9: Find and remove the task

```javascript
const task = deleteButton.closest("li");

if (task) {
    task.remove();
}
```

We find the task's `li` and remove it from the DOM.

### Why does this project demonstrate event delegation?

Suppose the user adds 20 tasks.

There are now 20 Delete buttons.

But we still have only one click listener:

```javascript
taskList.addEventListener("click", function (event) {
    // Handle delete button clicks
});
```

We do not attach 20 separate click listeners.

The same listener handles clicks on all matching buttons, including buttons created after the listener was registered.

This is the main advantage of event delegation.

## 13. Event Delegation vs Individual Event Listeners

| Individual event listeners | Event delegation |
|---|---|
| Listener attached to each child | Listener attached to a common parent |
| Can require many listeners | Usually requires one listener for the delegated event |
| Newly added children need their own listeners | Newly added children can work automatically |
| Useful when each element needs independent event handling | Useful when many similar children share behavior |
| Does not require bubbling for direct listeners | Usually relies on bubbling |

### Advantages of Event Delegation

1. **Fewer listeners:** One parent listener can handle many child elements.
2. **Dynamic elements:** Newly inserted matching elements can be handled automatically.
3. **Centralized logic:** Related event-handling code can be kept together.
4. **Convenient maintenance:** You do not need to register and remove a listener for every dynamically created child.

### Limitations of Event Delegation

1. It relies on events reaching the parent listener, usually through bubbling.
2. You must correctly identify which child triggered the event.
3. A large parent container can receive unrelated events, so selectors and containment checks matter.
4. Not every event is suitable for delegation. For example, `focus` and `blur` do not bubble normally; `focusin` and `focusout` are alternatives that do bubble.

## 14. Common Mistakes

### Mistake 1: Confusing target and currentTarget

Incorrect understanding:

```javascript
event.target === event.currentTarget
```

They are not always equal.

Example:

```html
<div id="parent">
    <button id="child">Click Me</button>
</div>
```

If the parent listener handles the button's click:

- `event.target` is the button.
- `event.currentTarget` is the parent.

They can be equal when the event target itself is the element whose listener is executing.

### Mistake 2: Thinking preventDefault() stops bubbling

Incorrect:

```javascript
event.preventDefault();
```

This does not stop event propagation.

Use:

```javascript
event.stopPropagation();
```

when you want to stop propagation.

### Mistake 3: Thinking stopPropagation() prevents default actions

Incorrect assumption:

```javascript
event.stopPropagation();
```

This does not prevent a link from navigating or a form from performing its default submission.

Use:

```javascript
event.preventDefault();
```

when you need to cancel a cancelable default action.

### Mistake 4: Attaching listeners before dynamically creating elements

Example:

```javascript
const buttons = document.querySelectorAll(".delete");

buttons.forEach(function (button) {
    button.addEventListener("click", deleteTask);
});
```

If new buttons are created afterward, this code does not automatically attach listeners to them.

Solution: Use event delegation or explicitly register a listener when creating each button.

### Mistake 5: Using event.target.matches() without considering nested elements

Example:

```javascript
if (event.target.matches(".delete")) {
    console.log("Delete clicked");
}
```

This works when the button itself is clicked.

But if the button contains a nested `span` and the user clicks the `span`, the target is the `span`.

Better:

```javascript
const button = event.target.closest(".delete");

if (button) {
    console.log("Delete clicked");
}
```

Also check that the matched element belongs to the intended container.

### Mistake 6: Assuming all events bubble

Not all events bubble.

Examples:

- `click` bubbles.
- `input` bubbles.
- `change` bubbles.
- `focus` does not bubble normally.
- `blur` does not bubble normally.

Always consider the event type before using event delegation.

### Mistake 7: Calling stopPropagation() unnecessarily

Stopping propagation can interfere with other components that rely on events reaching ancestor elements.

Use it only when you have a specific reason.

```html
</script>
```

2. Three list items appear.
3. Click Item 2.
4. Console displays:

```text
You clicked: Item 2
```

The same parent listener handles every item, including those created after the listener was registered.

## 16. Interview and Viva Questions

### Q1. What is the Event Object in JavaScript?

The Event Object is an object automatically passed to an event listener when an event occurs. It provides information about the event, including its type, target, current target, and other event-specific details.

### Q2. What is event propagation?

Event propagation is the process through which an event travels through the DOM tree. It consists of capturing, target, and bubbling phases.

### Q3. What are the three phases of event propagation?

1. Capturing phase.
2. Target phase.
3. Bubbling phase.

### Q4. What is event bubbling?

Event bubbling is the phase in which an event travels from the target element upward through its ancestors.

### Q5. What is event capturing?

Event capturing is the phase in which an event travels from outer ancestors toward the target element.

### Q6. What is the difference between event bubbling and event capturing?

Bubbling travels from child to parent, whereas capturing travels from parent to child.

### Q7. What is the difference between event.target and event.currentTarget?

`event.target` identifies the original event target, while `event.currentTarget` identifies the element whose listener is currently executing.

### Q8. What is preventDefault()?

`preventDefault()` cancels the browser's default action for an event when that action is cancelable and the listener is not passive.

### Q9. What is stopPropagation()?

`stopPropagation()` prevents an event from continuing through the DOM propagation path. It does not cancel the browser's default action.

### Q10. What is stopImmediatePropagation()?

It stops further propagation and prevents other listeners on the same target from running after it is called.

### Q11. What is event delegation?

Event delegation is a technique in which a listener is attached to a common parent to handle events originating from its child elements. It commonly uses event bubbling and `event.target` or `closest()` to identify the relevant child.

### Q12. What are the advantages of event delegation?

- Reduces the number of event listeners.
- Handles dynamically created child elements.
- Centralizes event-handling logic.
- Makes certain dynamic interfaces easier to maintain.

### Q13. Why does event delegation work?

It works because many DOM events bubble from child elements to their ancestors. The parent listener can therefore receive an event originating from a child.

### Q14. Does every event bubble?

No. Some events, such as `focus` and `blur`, do not bubble normally. Bubbling alternatives include `focusin` and `focusout`.

### Q15. Can we use event delegation for dynamically created elements?

Yes. If a suitable event bubbles to the parent, a listener already attached to that parent can handle events from matching elements created later.

### Q16. What is the difference between matches() and closest()?

`matches()` checks whether the element itself matches a CSS selector.

`closest()` checks the element itself and then searches its ancestors for the nearest matching element.

### Q17. Does preventDefault() stop event bubbling?

No. It cancels a default browser action, not event propagation.

### Q18. Does stopPropagation() prevent the default browser action?

No. It stops further propagation, but the default browser action can still occur.
