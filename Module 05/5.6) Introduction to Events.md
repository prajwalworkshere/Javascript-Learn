# Topic 5.6: Events and Event Listeners in JavaScript

## 1. Introduction to Events

Until now, we have learned how JavaScript can:

- Select HTML elements.
- Change text and HTML content.
- Modify CSS styles and classes.
- Create, insert, and remove HTML elements.

But there is one important question:

**How does JavaScript know when a user clicks a button, types something, or submits a form?**

The answer is **Events**.

### What is an Event?

An event is an action or occurrence that happens in the browser and can be detected by JavaScript.

Events can be triggered by:
- The user interacting with a webpage.
- The browser loading or changing a document.
- JavaScript programmatically triggering certain events.

Examples:

| User or browser action | Event |
|---|---|
| User clicks a button | `click` |
| User double-clicks an element | `dblclick` |
| User types in an input field | `input` |
| User changes an input value | `change` |
| User presses a keyboard key | `keydown` |
| User releases a keyboard key | `keyup` |
| User submits a form | `submit` |
| An element receives focus | `focus` |
| An element loses focus | `blur` |
| The HTML document has been parsed | `DOMContentLoaded` |

### Simple real-world example

Imagine a login page:

1. A user enters their username.
2. A user enters their password.
3. A user clicks the Login button.
4. JavaScript detects the click event.
5. JavaScript executes a function to process the login.

The click is an **event**, and the function that runs in response is an **event handler**.

---

## 2. What is Event Handling?

Event handling is the process of detecting an event and executing JavaScript code in response to it.

It generally involves three parts:

1. **Event target:** The element on which the event occurs or is listened for.
2. **Event type:** The name of the event, such as `click`.
3. **Event handler/listener:** The function that executes when the event occurs.

Example:

```html
<button id="myButton">Click Me</button>

<script>
    const button = document.getElementById("myButton");

    button.addEventListener("click", function () {
        console.log("Button was clicked!");
    });
</script>
```

**Output after clicking the button:**

```text
Button was clicked!
```

### Understanding the code

```javascript
const button = document.getElementById("myButton");
```

Selects the button from the HTML document.

```javascript
button.addEventListener("click", function () {
```

Registers an event listener for the `click` event.

```javascript
console.log("Button was clicked!");
```

This statement runs when the button is clicked.

Important: Registering an event listener does not immediately execute its callback function. The function runs when the specified event occurs.

---

## 3. Three Ways to Handle Events

JavaScript provides different ways to attach event-handling logic to HTML elements.

The three commonly discussed approaches are:

1. Inline HTML event handlers.
2. DOM event handler properties.
3. `addEventListener()`.

### 3.1 Inline HTML Event Handlers

In this approach, the event handler is written directly inside an HTML attribute.

Syntax:

```html
<element event="JavaScript code">
```

Example:

```html
<button onclick="showMessage()">Click Me</button>

<script>
    function showMessage() {
        alert("Hello! Button clicked.");
    }
</script>
```

When the button is clicked, `showMessage()` executes.

**How it works:**

- `onclick` is an HTML event-handler attribute.
- `showMessage()` is the JavaScript function being called.
- The browser invokes the function when the click occurs.

**Disadvantages:**

- HTML and JavaScript become mixed.
- It can make large applications harder to maintain.
- It is less convenient for organizing multiple event handlers.
- It can conflict with a strict Content Security Policy that blocks inline event handlers.

Inline handlers are useful to recognize in existing code, but `addEventListener()` is generally preferred for modern development.

### 3.2 DOM Event Handler Properties

In this approach, JavaScript assigns a function to an event-handler property of an element.

Syntax:

```javascript
element.onevent = function () {
    // JavaScript code
};
```

Example:

```html
<button id="myButton">Click Me</button>

<script>
    const button = document.getElementById("myButton");

    button.onclick = function () {
        alert("Button clicked!");
    };
</script>
```

Here:

- `button` refers to the selected HTML element.
- `onclick` is its click event-handler property.
- The assigned function runs when the button is clicked.

#### Important: Only one handler property at a time

Consider:

```javascript
const button = document.getElementById("myButton");

button.onclick = function () {
    console.log("First handler");
};

button.onclick = function () {
    console.log("Second handler");
};
```

**Output after clicking:**

```text
Second handler
```

Why?

The second assignment replaces the first function stored in the `onclick` property.

The first handler is no longer registered through that property.

### 3.3 Using addEventListener()

`addEventListener()` is the recommended general approach for attaching event listeners.

Syntax:

```javascript
element.addEventListener(eventType, callbackFunction, options);
```

Parameters:

| Parameter | Meaning |
|---|---|
| `eventType` | Event name, such as `"click"` or `"input"` |
| `callbackFunction` | Function that runs when the event occurs |
| `options` | Optional configuration for the listener |

Example:

```html
<button id="myButton">Click Me</button>

<script>
    const button = document.getElementById("myButton");

    button.addEventListener("click", function () {
        console.log("First handler");
    });

    button.addEventListener("click", function () {
        console.log("Second handler");
    });
</script>
```

**Output after clicking:**

```text
First handler
Second handler
```

Both listeners are registered, so both functions run.

### Comparison of the three approaches

| Feature | Inline handler | Event property | `addEventListener()` |
|---|---|---|---|
| Where written | HTML attribute | JavaScript | JavaScript |
| Multiple handlers for same event | Not conveniently | No, assignment replaces previous handler | Yes |
| Can remove a specific registered listener | Not through the attribute itself | Can set property to `null` | Yes, with `removeEventListener()` |
| Separates HTML and JavaScript | No | Yes | Yes |
| General recommendation | Avoid for most application code | Useful for simple cases | Preferred |

## 4. Understanding addEventListener() in Depth

Let's understand its syntax carefully.

```javascript
element.addEventListener("click", function () {
    console.log("Clicked");
});
```

### Step-by-step execution

**Step 1:** JavaScript selects the element.

```javascript
const button = document.getElementById("myButton");
```

**Step 2:** JavaScript registers a listener.

```javascript
button.addEventListener("click", function () {
    console.log("Clicked");
});
```

**Step 3:** The browser waits for the click event.

**Step 4:** The user clicks the button.

**Step 5:** The browser invokes the registered callback function.

**Step 6:** The message is printed.

Remember:

```javascript
button.addEventListener("click", showMessage);
```

This is correct.

But:

```javascript
button.addEventListener("click", showMessage());
```

Usually this is incorrect when you intend to register `showMessage` as the listener.

Why?

- `showMessage` passes the function itself.
- `showMessage()` calls the function immediately and passes its return value.

Correct:

```javascript
function showMessage() {
    console.log("Button clicked");
}

button.addEventListener("click", showMessage);
```

## 5. Using Different Types of Functions as Event Listeners

You can register different kinds of JavaScript functions as event listeners.

### 5.1 Function Declaration

```javascript
function greet() {
    console.log("Hello!");
}

button.addEventListener("click", greet);
```

### 5.2 Function Expression

```javascript
const greet = function () {
    console.log("Hello!");
};

button.addEventListener("click", greet);
```

### 5.3 Arrow Function

```javascript
button.addEventListener("click", () => {
    console.log("Hello!");
});
```

All three approaches work.

Choose the one that makes your code easiest to understand and maintain.

## 6. Common JavaScript Events

Let's explore the important events used in web development.

### 6.1 Mouse Events

Mouse events occur when a user interacts with an element using a mouse or a similar pointing device.

| Event | Description |
|---|---|
| `click` | A pointing-device click |
| `dblclick` | A double-click |
| `mousedown` | A mouse button is pressed |
| `mouseup` | A mouse button is released |
| `mousemove` | The pointer moves |
| `mouseover` | The pointer enters an element or one of its descendants |
| `mouseout` | The pointer leaves an element or one of its descendants |
| `mouseenter` | The pointer enters an element |
| `mouseleave` | The pointer leaves an element |

Example: Click event

```html
<button id="clickButton">Click</button>

<script>
    const button = document.getElementById("clickButton");

    button.addEventListener("click", function () {
        console.log("Clicked!");
    });
</script>
```

Example: Mouse enter and leave

```html
<div id="box">Move your mouse here</div>

<script>
    const box = document.getElementById("box");

    box.addEventListener("mouseenter", function () {
        box.style.backgroundColor = "lightgreen";
    });

    box.addEventListener("mouseleave", function () {
        box.style.backgroundColor = "lightblue";
    });
</script>
```

**Practical use cases:**
- Hover effects.
- Interactive menus.
- Image previews.
- Drag-and-drop interfaces.

Note: CSS `:hover` is often simpler for purely visual hover effects. JavaScript mouse events are useful when hovering must trigger application logic.

### 6.2 Keyboard Events

Keyboard events occur when a user interacts with the keyboard.

| Event | Description |
|---|---|
| `keydown` | A key is pressed down |
| `keyup` | A pressed key is released |

Example:

```html
<input type="text" id="username" placeholder="Type something">

<script>
    const input = document.getElementById("username");

    input.addEventListener("keydown", function () {
        console.log("A key was pressed");
    });

    input.addEventListener("keyup", function () {
        console.log("A key was released");
    });
</script>
```

When you type a character, the browser typically dispatches a `keydown` event, then an `input` event if the value changes, and then a `keyup` event when the key is released.

The exact sequence can vary depending on the input method and interaction.

**Practical use cases:**
- Keyboard shortcuts.
- Game controls.
- Search interfaces.
- Detecting Enter or Escape.

Example: Detect the Enter key.

```html
<input type="text" id="message" placeholder="Type and press Enter">

<script>
    const input = document.getElementById("message");

    input.addEventListener("keydown", function (event) {
        if (event.key === "Enter") {
            console.log("Enter key pressed!");
        }
    });
</script>
```

Here, `event.key` tells us which key was pressed.

We will study the event object in more depth in Topic 5.7.

### 6.3 Input Events

Input events are especially important when working with forms.

| Event | Description |
|---|---|
| `input` | Fires when the user changes the value of an input through an editing action |
| `change` | Fires when a value change is committed; its timing depends on the control |

Example: Input event

```html
<input type="text" id="name" placeholder="Enter your name">

<p id="output"></p>

<script>
    const nameInput = document.getElementById("name");
    const output = document.getElementById("output");

    nameInput.addEventListener("input", function () {
        output.textContent = nameInput.value;
    });
</script>
```

**Result:**

When you type `Prajwal`, the paragraph updates as you type.

Example: Change event

```html
<select id="course">
    <option value="">Choose a course</option>
    <option value="JavaScript">JavaScript</option>
    <option value="Python">Python</option>
    <option value="Java">Java</option>
</select>

<script>
    const course = document.getElementById("course");

    course.addEventListener("change", function () {
        console.log("Selected course:", course.value);
    });
</script>
```

When the selection is changed and committed, the selected value is displayed.

### Difference between input and change

| `input` | `change` |
|---|---|
| Detects editing changes as they happen | Detects a committed change |
| Commonly used for live updates | Commonly used when a selection or value is committed |
| Useful for live search and character counters | Useful for dropdown selections and committed form values |

The exact timing of `change` differs between control types. For example, text inputs generally fire it when the edited value is committed, often after the field loses focus.

### 6.4 Form Events

Form events are used when working with HTML forms.

Important events:

- `submit`
- `reset`

Example:

```html
<form id="loginForm">
    <input type="text" id="username" placeholder="Username">

    <button type="submit">Login</button>
</form>

<script>
    const form = document.getElementById("loginForm");

    form.addEventListener("submit", function (event) {
        event.preventDefault();

        console.log("Form submitted!");
    });
</script>
```

**Important concept:**

```javascript
event.preventDefault();
```

This prevents the browser's default action.

For a form, the default action commonly involves submitting the form and navigating or reloading the page according to its configuration.

We will study form handling and validation in Topic 5.8.

### 6.5 Focus Events

Focus events occur when an element receives or loses focus.

| Event | Description |
|---|---|
| `focus` | An element receives focus |
| `blur` | An element loses focus |
| `focusin` | An element or one of its descendants receives focus; bubbles |
| `focusout` | An element or one of its descendants loses focus; bubbles |

Example:

```html
<input type="text" id="email" placeholder="Enter email">

<script>
    const email = document.getElementById("email");

    email.addEventListener("focus", function () {
        email.style.backgroundColor = "lightyellow";
    });

    email.addEventListener("blur", function () {
        email.style.backgroundColor = "white";
    });
</script>
```

**Result:**
- When the input receives focus, its background becomes yellow.
- When it loses focus, its background becomes white.

### 6.6 Browser and Document Events

Some events are related to the browser or document rather than a direct user interaction.

Important examples:

| Event | Description |
|---|---|
| `DOMContentLoaded` | The HTML document has been completely parsed, and deferred/module scripts have executed |
| `load` | A resource and its dependent resources have finished loading |
| `resize` | The document view has been resized |
| `scroll` | An element or document view has been scrolled |

#### DOMContentLoaded

Example:

```javascript
document.addEventListener("DOMContentLoaded", function () {
    console.log("HTML document is ready!");
});
```

This is useful when JavaScript needs to access HTML elements after the browser has parsed the document.

`DOMContentLoaded` does not wait for images, stylesheets, and other external resources to finish loading.

#### load

```javascript
window.addEventListener("load", function () {
    console.log("Page resources have loaded!");
});
```

The `load` event on `window` waits for the page and its dependent resources to finish loading.

### DOMContentLoaded vs load

| DOMContentLoaded | load |
|---|---|
| Fires after HTML parsing and deferred/module script execution | Fires after the page and its dependent resources have loaded |
| Does not wait for images to finish loading | Waits for images and other dependent resources |
| Useful for DOM initialization | Useful when fully loaded resources are required |

## 7. Complete Practical Example: Interactive Counter

Let's build a counter application using event listeners.

### HTML + CSS + JavaScript

```html
<!DOCTYPE html>
<html>
<head>
    <title>Counter App</title>

    <style>
        body {
            font-family: Arial, sans-serif;
            text-align: center;
            margin-top: 100px;
        }

        button {
            padding: 10px 20px;
            margin: 5px;
            cursor: pointer;
        }

        #count {
            font-size: 30px;
        }
    </style>
</head>
<body>

    <h1>Counter Application</h1>

    <p id="count">0</p>

    <button id="decrease">Decrease</button>
    <button id="reset">Reset</button>
    <button id="increase">Increase</button>

    <script>
        let count = 0;

        const countDisplay = document.getElementById("count");

        const increaseButton = document.getElementById("increase");
        const decreaseButton = document.getElementById("decrease");
        const resetButton = document.getElementById("reset");

        increaseButton.addEventListener("click", function () {
            count++;
            countDisplay.textContent = count;
        });

        decreaseButton.addEventListener("click", function () {
            count--;
            countDisplay.textContent = count;
        });

        resetButton.addEventListener("click", function () {
            count = 0;
            countDisplay.textContent = count;
        });
    </script>

</body>
</html>
```

### Expected result

Initially:

```text
Counter Application

0

Decrease   Reset   Increase
```

After clicking Increase three times:

```text
3
```

After clicking Decrease once:

```text
2
```

After clicking Reset:

```text
0
```

### Understanding the execution

Initially:

```javascript
let count = 0;
```

The counter value is zero.

When Increase is clicked:

```javascript
count++;
countDisplay.textContent = count;
```

The value increases by one, and the paragraph is updated.

When Decrease is clicked:

```javascript
count--;
countDisplay.textContent = count;
```

The value decreases by one, and the paragraph is updated.

When Reset is clicked:

```javascript
count = 0;
countDisplay.textContent = count;
```

The value becomes zero again.

### Dry run

| Action | Previous count | Operation | New count |
|---|---:|---|---:|
| Initial | — | Initialize | 0 |
| Increase | 0 | `count++` | 1 |
| Increase | 1 | `count++` | 2 |
| Increase | 2 | `count++` | 3 |
| Decrease | 3 | `count--` | 2 |
| Reset | 2 | `count = 0` | 0 |

**Important:** The event listener does not repeatedly run by itself. Each time the user clicks a button, the browser dispatches a click event and invokes the corresponding registered listener.

## 8. Removing Event Listeners

JavaScript provides:

```javascript
element.removeEventListener(eventType, callbackFunction);
```

It removes a previously registered event listener.

### Example

```html
<button id="myButton">Click Me</button>
<button id="removeButton">Remove Listener</button>

<script>
    const button = document.getElementById("myButton");
    const removeButton = document.getElementById("removeButton");

    function showMessage() {
        console.log("Button clicked!");
    }

    button.addEventListener("click", showMessage);

    removeButton.addEventListener("click", function () {
        button.removeEventListener("click", showMessage);

        console.log("Listener removed!");
    });
</script>
```

**Expected behavior:**

1. Click the first button: `Button clicked!` appears.
2. Click Remove Listener: `Listener removed!` appears.
3. Click the first button again: nothing happens.

### Important rule: Use the same function reference

Correct:

```javascript
function greet() {
    console.log("Hello");
}

button.addEventListener("click", greet);

button.removeEventListener("click", greet);
```

Incorrect:

```javascript
button.addEventListener("click", function () {
    console.log("Hello");
});

button.removeEventListener("click", function () {
    console.log("Hello");
});
```

Why is the second example incorrect?

Both anonymous functions have the same code, but they are different function objects.

`removeEventListener()` needs the same function reference that was registered.

### Using an arrow function reference

```javascript
const greet = () => {
    console.log("Hello");
};

button.addEventListener("click", greet);
button.removeEventListener("click", greet);
```

This works because the same function reference is used both times.

### Important removal rule

For reliable removal, match:

- The same event type.
- The same callback function reference.
- The same `capture` setting.

Other options such as `once` and `passive` do not need to be repeated for removal.

## 9. Event Listener Options

The third argument of `addEventListener()` can configure how the listener behaves.

Syntax:

```javascript
element.addEventListener("click", callback, options);
```

Some important options are:

| Option | Meaning |
|---|---|
| `capture` | Controls whether the listener participates in the capturing phase |
| `once` | Automatically removes the listener after it runs once |
| `passive` | Indicates that the listener will not call `preventDefault()` |
| `signal` | Allows an `AbortSignal` to control removal of the listener |

### 9.1 once

Use `once: true` when a listener should run only one time.

```javascript
button.addEventListener("click", function () {
    console.log("This runs only once!");
}, {
    once: true
});
```

**Expected behavior:**

- First click: message appears.
- Second click: no message.
- Third click: no message.

The browser automatically removes the listener after its first invocation.

### 9.2 capture

```javascript
element.addEventListener("click", callback, {
    capture: true
});
```

This registers the listener for the capturing phase.

We will study capturing and bubbling in detail in Topic 5.7.

### 9.3 passive

```javascript
window.addEventListener("scroll", function () {
    console.log("Scrolling...");
}, {
    passive: true
});
```

A passive listener promises not to call `event.preventDefault()`.

This can help the browser optimize certain events, particularly scrolling-related events.

If `preventDefault()` is called inside a passive listener, it will not cancel the default action.

### 9.4 signal

An `AbortController` can be used to remove listeners.

```javascript
const controller = new AbortController();

button.addEventListener("click", function () {
    console.log("Clicked!");
}, {
    signal: controller.signal
});

// Remove listeners registered with this signal
controller.abort();
```

This is useful when you want to clean up several event listeners together.

## 10. The `this` Keyword in Event Listeners

When an ordinary function is used as an event listener, `this` refers to the element on which the listener was registered.

Example:

```html
<button id="myButton">Click Me</button>

<script>
    const button = document.getElementById("myButton");

    button.addEventListener("click", function () {
        console.log(this);
    });
</script>
```

When clicked, `this` refers to the button element.

You can use it to modify that element:

```javascript
button.addEventListener("click", function () {
    this.textContent = "Clicked!";
});
```

### Important: Arrow functions behave differently

```javascript
button.addEventListener("click", () => {
    console.log(this);
});
```

An arrow function does not create its own `this`. It inherits `this` from its surrounding lexical scope.

Therefore, `this` inside an arrow-function listener is not automatically the element.

### Recommended approach: event.currentTarget

You can use:

```javascript
button.addEventListener("click", (event) => {
    event.currentTarget.textContent = "Clicked!";
});
```

`event.currentTarget` refers to the element whose listener is currently executing.

This is often clearer and works consistently with ordinary and arrow functions.

## 11. Common Mistakes in Event Handling

### Mistake 1: Calling the function instead of passing it

Incorrect:

```javascript
button.addEventListener("click", showMessage());
```

Correct:

```javascript
button.addEventListener("click", showMessage);
```

Explanation: Pass the function reference so the browser can call it when the event occurs.

### Mistake 2: Selecting an element that does not exist yet

Problem:

```html
<script>
    const button = document.getElementById("myButton");

    button.addEventListener("click", function () {
        console.log("Clicked");
    });
</script>

<button id="myButton">Click</button>
```

The script runs before the browser has parsed the button. Therefore, `getElementById()` returns `null`, and attempting to call `addEventListener()` on `null` causes an error.

**Solution 1: Place the script after the HTML**

```html
<button id="myButton">Click</button>

<script>
    const button = document.getElementById("myButton");

    button.addEventListener("click", function () {
        console.log("Clicked");
    });
</script>
```

**Solution 2: Use defer**

```html
<head>
    <script src="script.js" defer></script>
</head>
```

The deferred script executes after the HTML document has been parsed.

**Solution 3: Use DOMContentLoaded**

```javascript
document.addEventListener("DOMContentLoaded", function () {
    const button = document.getElementById("myButton");

    button.addEventListener("click", function () {
        console.log("Clicked");
    });
});
```

### Mistake 3: Trying to remove an anonymous listener with a new function

Incorrect:

```javascript
button.addEventListener("click", function () {
    console.log("Hello");
});

button.removeEventListener("click", function () {
    console.log("Hello");
});
```

Correct:

```javascript
function greet() {
    console.log("Hello");
}

button.addEventListener("click", greet);
button.removeEventListener("click", greet);
```

### Mistake 4: Using `onclick` repeatedly when multiple handlers are required

Problem:

```javascript
button.onclick = firstFunction;
button.onclick = secondFunction;
```

The second assignment replaces the first.

Solution:

```javascript
button.addEventListener("click", firstFunction);
button.addEventListener("click", secondFunction);
```

### Mistake 5: Forgetting that a form submission can reload or navigate

Problem:

```javascript
form.addEventListener("submit", function () {
    console.log("Form submitted");
});
```

The browser may perform the form's default submission action after the handler runs.

If you are handling the form entirely with JavaScript, you may need:

```javascript
form.addEventListener("submit", function (event) {
    event.preventDefault();

    console.log("Form handled with JavaScript");
});
```

### Mistake 6: Assuming arrow-function `this` is the clicked element

Incorrect assumption:

```javascript
button.addEventListener("click", () => {
    this.textContent = "Clicked";
});
```

Use:

```javascript
button.addEventListener("click", (event) => {
    event.currentTarget.textContent = "Clicked";
});
```

### Mistake 7: Confusing `input` and `change`

Use `input` for immediate updates while the user edits a text field.

Use `change` when you need to react to a committed value change.

## 14. Interview and Viva Questions

### Q1. What is an event in JavaScript?

An event is an action or occurrence detected by the browser, such as a click, key press, input change, or form submission. JavaScript can respond to events by executing registered event-handler functions.

### Q2. What is event handling?

Event handling is the process of registering and executing JavaScript code in response to events occurring on HTML elements or browser objects.

### Q3. What is an event listener?

An event listener is a function registered to respond to a particular event on a target object. It is commonly registered using `addEventListener()`.

### Q4. What is `addEventListener()`?

`addEventListener()` is a JavaScript method used to register an event listener on an element or another event target.

Syntax:

```javascript
element.addEventListener("click", callback);
```

### Q5. What is the difference between `onclick` and `addEventListener()`?

`onclick` is an event-handler property that stores one handler at a time. `addEventListener()` allows multiple listeners for the same event and provides options such as `once`, `capture`, and `passive`.

### Q6. Can we attach multiple event listeners to one element?

Yes. We can register multiple listeners for the same event using `addEventListener()`.

```javascript
button.addEventListener("click", firstFunction);
button.addEventListener("click", secondFunction);
```

Both functions can execute when the button is clicked.

### Q7. What is `removeEventListener()`?

It removes a previously registered event listener.

```javascript
element.removeEventListener("click", callback);
```

The same event type, callback reference, and capture setting must match.

### Q8. What is the difference between `keydown` and `keyup`?

- `keydown` occurs when a keyboard key is pressed.
- `keyup` occurs when a pressed key is released.

### Q9. What is the difference between `input` and `change`?

`input` detects editing changes as they happen. `change` detects a committed change, with timing that depends on the type of form control.

### Q10. What is the purpose of `event.preventDefault()`?

It prevents the browser's default action associated with an event, when that action is cancelable.

For example, it can prevent a form from performing its normal submission navigation.

### Q11. What is the purpose of the `once` option?

It makes an event listener execute at most once. The browser removes it after its first invocation.

### Q12. What is the difference between `DOMContentLoaded` and `load`?

`DOMContentLoaded` fires after the HTML document is parsed and deferred/module scripts have executed. `load` fires after the page and its dependent resources have finished loading.

### Q13. What happens if we call a function while registering an event listener?

If we write:

```javascript
button.addEventListener("click", greet());
```

The function is called immediately, and its return value is passed instead of the function reference.

Usually, we should write:

```javascript
button.addEventListener("click", greet);
```

### Q14. Can arrow functions be used as event listeners?

Yes. Arrow functions can be registered as event listeners. However, they inherit `this` from their surrounding scope rather than receiving the event target as their own `this`.

Use `event.currentTarget` when you need the element whose listener is executing.

### Q15. Why is `addEventListener()` generally preferred?

It keeps JavaScript separate from HTML, supports multiple listeners for the same event, and provides flexible listener options and removal.

## 15. Quick Revision

### Important terms

| Term | Meaning |
|---|---|
| Event | An action or occurrence detected by the browser |
| Event target | The object on which an event occurs or is listened for |
| Event type | Name of the event, such as `click` |
| Event handler | Function that handles an event |
| Event listener | Registered function that responds to an event |
| `addEventListener()` | Registers an event listener |
| `removeEventListener()` | Removes a registered event listener |
| `preventDefault()` | Prevents a cancelable default browser action |
| `once` | Runs a listener only once |
| `DOMContentLoaded` | Signals that the document has been parsed and deferred/module scripts have executed |

### Important syntax

```javascript
// Register an event listener
element.addEventListener("click", callback);

// Register an anonymous function
element.addEventListener("click", function () {
    console.log("Clicked");
});

// Register an arrow function
element.addEventListener("click", () => {
    console.log("Clicked");
});

// Remove an event listener
element.removeEventListener("click", callback);

// Run a listener only once
element.addEventListener("click", callback, {
    once: true
});

// Prevent the default browser action
element.addEventListener("submit", function (event) {
    event.preventDefault();
});
```
