# 1. Introduction

JavaScript programs contain instructions that tell the computer what to do.

For example:

```javascript
console.log("Hello");

console.log("Welcome");

console.log("JavaScript");
```

When this program executes, JavaScript processes the statements in sequence.

But what happens when a program needs to perform an operation that takes time?

For example:

- Fetching data from a server.
- Reading a file.
- Waiting for a timer.
- Sending a request to a database.
- Loading information from an external API.

Should JavaScript stop executing everything until that operation finishes?

If it did, applications could become slow and unresponsive.

To understand how JavaScript handles such situations, we need to understand two execution approaches:

1. Synchronous JavaScript
2. Asynchronous JavaScript

## 1.1 What is synchronous JavaScript?

Synchronous JavaScript executes statements one after another. Each statement must finish before the next statement begins.

**In simple words:**

Complete the current task first, then move to the next task.

## 1.2 What is asynchronous JavaScript?

Asynchronous JavaScript allows certain operations to be initiated without making the remaining JavaScript code wait for those operations to finish.

The operation can complete later, and its result can be handled when it becomes available.

**In simple words:**

Start a task, continue doing other work, and handle the result when it is ready.

## 1.3 Why do we need asynchronous JavaScript?

Imagine a website that needs to retrieve user information from a server.

The request might take a few seconds.

Without asynchronous handling, waiting for the request could prevent other JavaScript work from proceeding.

Asynchronous JavaScript helps applications remain responsive while waiting for operations such as:

- Network requests.
- Timers.
- File operations.
- Database communication.
- Other runtime-managed operations.

# 4. Synchronous JavaScript

## 4.1 Definition

**Synchronous JavaScript is an execution model in which statements are executed sequentially, with each statement completing before the next statement begins.**

In synchronous execution, JavaScript follows the order of the instructions.

If one operation takes a long time, the subsequent statements must wait for it to finish.

## 4.2 How synchronous execution works

Consider:

```javascript
console.log("Task 1");

console.log("Task 2");

console.log("Task 3");
```

### Expected Output

```text
Task 1
Task 2
Task 3
```

### Explanation

**Step 1:**

```javascript
console.log("Task 1");
```

JavaScript executes the first statement and prints:

```text
Task 1
```

**Step 2:**

```javascript
console.log("Task 2");
```

After the first statement finishes, JavaScript executes the second statement.

Output:

```text
Task 2
```

**Step 3:**

```javascript
console.log("Task 3");
```

After the second statement finishes, JavaScript executes the third statement.

Output:

```text
Task 3
```

### Dry Run

| Step | Statement | Output |
|---|---|---|
| 1 | `console.log("Task 1")` | Task 1 |
| 2 | `console.log("Task 2")` | Task 2 |
| 3 | `console.log("Task 3")` | Task 3 |

### Important Point

JavaScript does not skip the current statement and execute the next statement first.

It follows the execution sequence.

---

## 4.3 Synchronous Execution with Functions

A normal function call is synchronous.

When JavaScript encounters a function call, it executes the function before proceeding to the next statement.

### Example

```javascript
function firstTask() {
    console.log("First task started");

    console.log("First task completed");
}

function secondTask() {
    console.log("Second task started");

    console.log("Second task completed");
}

firstTask();

secondTask();
```

### Expected Output

```text
First task started
First task completed
Second task started
Second task completed
```

### Line-by-Line Explanation

**Function 1:**

```javascript
function firstTask() {
    console.log("First task started");

    console.log("First task completed");
}
```

This defines a function named `firstTask`.

It contains two statements.

**Function 2:**

```javascript
function secondTask() {
    console.log("Second task started");

    console.log("Second task completed");
}
```

This defines another function named `secondTask`.

**Function call:**

```javascript
firstTask();
```

JavaScript executes all the statements inside `firstTask()`.

Only after the function finishes does execution continue.

**Second function call:**

```javascript
secondTask();
```

JavaScript now executes the statements inside `secondTask()`.

### Dry Run

| Step | Execution | Output |
|---|---|---|
| 1 | Call `firstTask()` | |
| 2 | Execute first statement inside it | First task started |
| 3 | Execute second statement inside it | First task completed |
| 4 | `firstTask()` finishes | |
| 5 | Call `secondTask()` | |
| 6 | Execute first statement inside it | Second task started |
| 7 | Execute second statement inside it | Second task completed |

### Execution Diagram

```text
             PROGRAM START
                   |
                   v
          Call firstTask()
                   |
                   v
       First task started
                   |
                   v
      First task completed
                   |
                   v
         firstTask() ends
                   |
                   v
         Call secondTask()
                   |
                   v
      Second task started
                   |
                   v
     Second task completed
                   |
                   v
        secondTask() ends
                   |
                   v
             PROGRAM END
```

**Remember:** A normal function is not automatically asynchronous. It executes synchronously when called unless it initiates or uses asynchronous behavior.

## 4.4 Blocking in Synchronous JavaScript

### What is blocking?

Blocking means an operation prevents further work from proceeding until that operation completes.

A long-running synchronous operation can block JavaScript execution.

### Example: Blocking Loop

```javascript
console.log("Program started");

let start = Date.now();

while (Date.now() - start < 3000) {
    // Loop continues for approximately 3 seconds
}

console.log("Program completed");
```

### Expected Output

```text
Program started
Program completed
```

However, the second message appears only after approximately three seconds.

### Explanation

**Line 1:**

```javascript
console.log("Program started");
```

Prints the first message.

**Line 3:**

```javascript
let start = Date.now();
```

Stores the current time in milliseconds.

**Line 5:**

```javascript
while (Date.now() - start < 3000) {
}
```

The loop repeatedly checks whether three seconds have elapsed.

While the condition is true, the loop continues running.

Because this is synchronous code, JavaScript cannot proceed to the next statement until the loop finishes.

**Final statement:**

```javascript
console.log("Program completed");
```

This executes after the loop ends.

### Execution Diagram

```text
       PROGRAM STARTS
              |
              v
    Print "Program started"
              |
              v
       Start while loop
              |
              v
      +-------------------+
      |                   |
      |  Check elapsed    |
      |  time             |
      |                   |
      |  Less than 3 sec? |
      |                   |
      +-------------------+
              |
        Yes   |   No
         |    |    |
         v    |    v
     Repeat   |  Exit loop
         |    |    |
         +----+    |
                   v
       Print "Program completed"
                   |
                   v
             PROGRAM ENDS
```

### Why is blocking a problem?

In a browser, long-running JavaScript on the main thread can make a page unresponsive.

For example:

- Buttons may not respond.
- Animations may freeze.
- User interactions may be delayed.
- The page may appear stuck.

This is one reason asynchronous programming is important.

# 5. Asynchronous JavaScript

## 5.1 Definition

**Asynchronous JavaScript is an execution approach in which certain operations can be initiated without blocking the remaining JavaScript code while those operations are pending. Their results can be handled later.**

In simple words:

Start a task, continue with other work, and handle the first task when its result is ready.

## 5.2 Real-Life Analogy

Imagine ordering food at a restaurant.

1. You place your order.
2. The restaurant starts preparing your food.
3. You do not stand still doing nothing.
4. You can talk to your friends or do other activities.
5. When the food is ready, the restaurant serves it.

This is similar to asynchronous programming.

The application starts an operation and can continue with other work while waiting for its completion.

---

## 5.3 Understanding `setTimeout()`

JavaScript provides a function called `setTimeout()` that schedules a callback function to execute after a specified delay.

### Syntax

```javascript
setTimeout(callbackFunction, delayInMilliseconds);
```

### Components

| Component | Explanation |
|---|---|
| `setTimeout` | Function used to schedule a callback for later execution. |
| `callbackFunction` | Function that will be called later. |
| `delayInMilliseconds` | Minimum delay before the callback becomes eligible to execute. |

### Understanding Milliseconds

| Milliseconds | Equivalent Time |
|---|---|
| 1000 ms | 1 second |
| 2000 ms | 2 seconds |
| 3000 ms | 3 seconds |
| 5000 ms | 5 seconds |

---

## 5.4 First Asynchronous Example

```javascript
console.log("Task 1");

setTimeout(function () {
    console.log("Task 2");
}, 3000);

console.log("Task 3");
```

### Expected Output

```text
Task 1
Task 3
Task 2
```

The second message appears after approximately three seconds, assuming the runtime is free to process the callback.

### Line-by-Line Explanation

**Line 1:**

```javascript
console.log("Task 1");
```

JavaScript immediately prints:

```text
Task 1
```

**Line 3:**

```javascript
setTimeout(function () {
```

JavaScript encounters `setTimeout()`.

It schedules the callback function to execute later.

The callback is not executed immediately.

**Line 4:**

```javascript
console.log("Task 2");
```

This statement is inside the callback function.

It executes when the callback eventually runs.

**Line 5:**

```javascript
}, 3000);
```

The delay is 3000 milliseconds, equivalent to three seconds.

**Line 7:**

```javascript
console.log("Task 3");
```

JavaScript does not wait for the timer to finish.

It continues executing and prints:

```text
Task 3
```

After the timer delay has elapsed, the callback becomes eligible to execute.

When JavaScript can process it, the callback prints:

```text
Task 2
```

### Final Output

```text
Task 1
Task 3
Task 2
```

Consider the following code again:


### Step-by-Step Dry Run

| Step | Operation | Result |

| 1 | JavaScript starts execution | Program begins |
| 2 | Executes first `console.log()` | Prints Task 1 |
| 3 | Encounters `setTimeout()` | Schedules callback |
| 4 | Timer begins in the runtime environment | JavaScript continues |
| 5 | Executes final `console.log()` | Prints Task 3 |
| 6 | Timer reaches its delay | Callback becomes eligible |
| 7 | Callback executes when JavaScript can process it | Prints Task 2 |

```text
                     |

            |                  |
```

### Important Understanding

`setTimeout()` does not pause the entire JavaScript program.

It schedules a callback and allows the remaining synchronous code to continue.

## 5.6 Timer Delay Is Not an Exact Execution Guarantee

Consider:

```javascript
setTimeout(() => {
    console.log("Hello");
}, 1000);
```

It is incorrect to say that the callback will always execute at exactly 1000 milliseconds.

The delay represents the minimum time before the callback can become eligible to execute.

If JavaScript is busy executing other work, the callback may execute later.

For example:

```javascript
console.log("Start");

setTimeout(() => {
    console.log("Timer completed");
}, 1000);

console.log("End");
```

Output:

```text
Start
End
Timer completed
```

The timer callback runs after the current synchronous code finishes and the runtime can process it.

# 6. Synchronous vs Asynchronous JavaScript

Now that we understand both concepts, let's compare them.

| Synchronous JavaScript | Asynchronous JavaScript |
|---|---|
| Executes statements sequentially. | Allows certain operations to complete later. |
| The current operation must finish before the next statement proceeds. | The program can continue while an asynchronous operation is pending. |
| Long-running operations can block execution. | Asynchronous waiting can avoid blocking the main JavaScript thread. |
| Execution is straightforward to follow in simple programs. | Useful for operations that take time. |
| Normal function calls are synchronous by default. | Timers, network requests and other runtime operations can be asynchronous. |
| Example: normal function execution. | Example: `setTimeout()` and `fetch()`. |

# 7. Is JavaScript Single-Threaded?

This is an important JavaScript interview question.

## 7.1 What does single-threaded mean?

JavaScript is commonly described as single-threaded in its main execution model.

It means JavaScript code in a given execution context is normally processed by one main call stack, which executes one piece of JavaScript at a time.

### Example

```javascript
console.log("First");

console.log("Second");

console.log("Third");
```

The main JavaScript execution processes the statements sequentially.

## 7.2 Then how does asynchronous JavaScript work?

JavaScript does not need to perform every waiting operation itself.

The runtime environment provides additional facilities for certain operations.

For example, in a browser:

- Browser timer facilities handle timers.
- Browser networking facilities handle network requests.
- Other browser APIs provide additional capabilities.

In Node.js:

- Node.js provides facilities for file operations.
- Networking operations can be handled through its runtime.
- Other asynchronous APIs are available.

JavaScript can initiate an operation and continue executing other code while the runtime handles the waiting or underlying work.

We will explore the exact interaction between JavaScript and its runtime environment in Topic 02.

### Conceptual Diagram

```text
             JAVASCRIPT PROGRAM
                     |
                     v
             JavaScript Runtime
                     |
          +----------+-----------+
          |                      |
          v                      v
   JavaScript execution     Runtime facilities
      (Call Stack)          (Timers, Network,
                             File operations)
          |                      |
          v                      v
   Executes available       Handles supported
   JavaScript code          asynchronous work
          |                      |
          +----------+-----------+
                     |
                     v
             Result handled later
```

# 8. Asynchronous vs Parallel Execution

These concepts are related but are not the same.

## 8.1 What is asynchronous execution?

Asynchronous execution means an operation can be started and handled later without blocking the current execution flow.

## 8.2 What is parallel execution?

Parallel execution means multiple operations are actually being processed at the same time.

## 8.3 Difference

| Asynchronous Execution | Parallel Execution |
|---|---|
| Work can complete later. | Multiple operations are processed simultaneously. |
| Does not necessarily require multiple JavaScript threads. | Requires the ability to execute work simultaneously. |
| Helps avoid waiting synchronously for certain operations. | Uses concurrent processing resources. |
| Example: scheduling a timer callback. | Example: computation using multiple worker threads. |

**Important interview point:**

Asynchronous execution does not automatically mean parallel execution.

JavaScript's main call stack still processes one piece of JavaScript at a time, even though the runtime can handle asynchronous operations.

# 9. Real-World Applications of Asynchronous JavaScript

Asynchronous JavaScript is essential in modern web applications.

## 9.1 Fetching Data from an API

Imagine a weather application.

When a user opens the application:

1. JavaScript sends a request to a weather API.
2. The server processes the request.
3. JavaScript can continue handling other work while waiting.
4. When the response arrives, the application processes and displays the data.

### Example

```javascript
console.log("Loading weather...");

fetch("https://jsonplaceholder.typicode.com/posts/1")
    .then(response => response.json())
    .then(data => {
        console.log(data);
    });

console.log("Application is still running");
```

### Conceptual Output Order

```text
Loading weather...
Application is still running
{ ...post data... }
```

The exact response data comes from the server.

Here:

- `fetch()` starts a network request.
- `.then()` registers functions to handle the result.
- JavaScript continues to the next statement.
- The response is handled later.

We will study Promises and Fetch API in later topics.

## 9.2 Timers and Notifications

```javascript
console.log("Timer started");

setTimeout(() => {
    console.log("Reminder: Take a break!");
}, 2000);

console.log("You can continue working");
```

### Output

```text
Timer started
You can continue working
Reminder: Take a break!
```

Common applications:

- Reminders.
- Notifications.
- Countdown features.
- Delayed messages.
- Temporary UI messages.

## 9.3 Form Submission

Imagine a user submits a registration form.

The application needs to send the form data to a server.

An asynchronous request allows the application to wait for the server response without blocking the entire interface.

## 9.4 Backend Applications

Node.js applications use asynchronous operations for tasks such as:

- Reading files.
- Writing files.
- Database communication.
- Network requests.
- Handling incoming connections.

# 10. Common Mistakes and Misconceptions

## Mistake 1: Thinking `setTimeout()` pauses JavaScript

Incorrect understanding:

```javascript
setTimeout(() => {
    console.log("Hello");
}, 2000);

// JavaScript waits here for two seconds.

console.log("Next");
```

Actual output:

```text
Next
Hello
```

**Correction:**

`setTimeout()` schedules the callback for later. It does not pause the entire JavaScript program.

## Mistake 2: Thinking the timer delay is exact

```javascript
setTimeout(() => {
    console.log("Hello");
}, 1000);
```

Incorrect understanding:

The callback will always execute at exactly 1000 milliseconds.

Correct understanding:

The callback becomes eligible after the specified minimum delay. It may execute later if JavaScript is busy.

## Mistake 3: Thinking every function is asynchronous

```javascript
function greet() {
    console.log("Hello");
}

greet();

console.log("Next");
```

Output:

```text
Hello
Next
```

**Correction:**

A normal function call is synchronous by default.

## Mistake 4: Thinking asynchronous means simultaneous JavaScript execution

Asynchronous execution does not mean multiple callbacks execute simultaneously on the same main JavaScript call stack.

It means certain operations can be handled later while other JavaScript work continues.

## Mistake 5: Thinking zero milliseconds means immediate execution

```javascript
console.log("One");

setTimeout(() => {
    console.log("Two");
}, 0);

console.log("Three");
```

Output:

```text
One
Three
Two
```

**Correction:**

A zero-delay timer is still scheduled for later. It does not interrupt the current synchronous execution.

# 12. Interview and Viva Questions

## Q1. What is synchronous JavaScript?

Synchronous JavaScript is an execution model in which statements execute sequentially, and each statement must complete before the next statement begins.

## Q2. What is asynchronous JavaScript?

Asynchronous JavaScript allows certain operations to be initiated without blocking the remaining JavaScript execution while those operations are pending. Their results can be handled later.

## Q3. What is the main difference between synchronous and asynchronous execution?

Synchronous execution waits for the current operation to finish before proceeding.

Asynchronous execution allows certain operations to complete later while other work continues.

## Q4. Is JavaScript single-threaded?

JavaScript's main execution model uses one main call stack to process JavaScript code one piece at a time. The runtime environment provides additional facilities for asynchronous operations.

## Q5. What is `setTimeout()`?

`setTimeout()` is a JavaScript function that schedules a callback function to execute after a specified minimum delay.

## Q6. Does `setTimeout()` block JavaScript execution?

No. It schedules a callback for later and allows the current synchronous code to continue executing.

## Q7. Does asynchronous execution mean parallel execution?

No. Asynchronous execution means an operation can be handled later without blocking the current flow. Parallel execution means multiple operations are processed simultaneously.

## Q8. Why is asynchronous JavaScript important?

It helps applications remain responsive while waiting for operations such as network requests, timers, and file operations.

## Q9. What is blocking code?

Blocking code prevents further work from proceeding until the current operation completes.

A long-running synchronous loop is an example.

## Q10. Give examples of asynchronous JavaScript operations.

Examples include:

- `setTimeout()`
- `setInterval()`
- `fetch()`
- Node.js file operations.
- Network communication.

## Q11. What is a callback function?

A callback is a function passed to another function so that it can be called later or under a particular condition.

Example:

```javascript
setTimeout(() => {
    console.log("Hello");
}, 1000);
```

Here, the arrow function is the callback passed to `setTimeout()`.

## Q12. What is the difference between synchronous and blocking?

Synchronous describes the execution order: one operation completes before the next statement proceeds.

Blocking describes the effect of an operation preventing other work from proceeding.

Synchronous operations can be very quick and need not cause noticeable delays. Long-running synchronous operations are the ones that commonly cause blocking problems.
